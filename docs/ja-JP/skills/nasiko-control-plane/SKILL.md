# Nasiko CLI ライフサイクルブリッジ

ユーザーが ECC に対して、検証済みの Nasiko CLI のインストール、確認、または削除を明示的に求めた場合にこのスキルを使用します。このスキルは Nasiko コントロールプレーンを操作するものではありません。

## 安全性の取り決め

- `ecc nasiko status --json` から開始します。ステータス確認は読み取り専用です。
- インストールには常にユーザーの明示的な同意と `--yes` が必要です。
- ECC が検証済みの固定バージョン（現在は `v0.1.0`）のみをインストールします。
- まず `ecc nasiko install --version v0.1.0 --dry-run --json` でプレビューします。
- ユーザーがバージョン、レジストリのオリジン、ダイジェスト、インストール先を確認した後にのみ、`ecc nasiko install --version v0.1.0 --yes --json` でインストールします。
- 検証済みの状態を保っている ECC 管理のバイナリのみを `ecc nasiko uninstall --version v0.1.0 --yes --json` で削除します。削除前に、まず `--dry-run` でプレビューします。
- 検証済みのソースは `https://github.com/Nasiko-Labs/nasiko` で、Apache-2.0 ライセンスです。アーティファクトおよび展開後のバイナリの SHA-256 値は固定されています。
- 検証済みのコマンドを、ダウンロードしたシェルスクリプトや PowerShell ブートストラップスクリプトで置き換えてはいけません。
- シークレットや認証情報を、コマンド引数、ログ、スキルの出力、インストールメタデータ、ECC の状態に含めてはいけません。
- Nasiko のテレメトリ、および Nasiko や Ito との共有はオプトインでなければならず、別途開示される必要があります。インストールはテレメトリへの同意ではありません。

## ライフサイクルの境界

ECC ブリッジの初期バージョンは、検証済みのインストール、読み取り専用のステータス確認、所有権チェック付きのアンインストールをサポートします。接続、認証、起動、デプロイ、シャットダウンについては、正規の Nasiko CLI を直接使用してください。これらのサブコマンドが ECC 側で独自に検証済みの契約を持つまでは、この扱いとします。CLI のサブコマンドを推測してはいけません。

CLI をインストールしても、コントロールプレーンサーバーが稼働していること、エージェントが管理下にあること、ルーティングや ACL が機能していること、可観測性が十分であること、テレメトリが有効化されていること、Ito のコンピュートが接続されていることは保証されません。それぞれの状態を個別に報告してください。

## 失敗時の動作

- プラットフォーム、アーキテクチャ、バージョン、マニフェスト、ダイジェスト、アーカイブ、バイナリ、インストール先のいずれかが検証に失敗した場合は、アーティファクトを実行せずに停止します。
- `latest` にフォールバックしてはいけません。
- 任意の `PATH` エントリを検索してはいけません。ECC の検証済みの場所、または開発時の検証用に明示的に指定された絶対パスの `ECC_NASIKO_CLI_EXECUTABLE` を使用します。
- 部分的または曖昧なインストールを成功として扱ってはいけません。
