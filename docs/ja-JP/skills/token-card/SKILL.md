# トークンカード

このマシンでの AI コーディングエージェントの使用状況（合計トークン数、API 換算コスト、現在の連続日数、エージェントごとの内訳）をまとめた SVG カードを生成し、README から参照できるファイルとして作業ツリーに書き出します。

カードはホスト型の画像ではなくコミットされる成果物であるため、リポジトリ自体から描画され、サードパーティのエンドポイントが稼働し続けることに依存しません。

## 有効化するタイミング

- README やドキュメントページに使用量の数値を表示したいとき
- 複数のツールにまたがるエージェント活動の共有可能なサマリーを求められたとき

質問が「今週いくら使ったか」である場合は、代わりに `/cost-report` を使用します。この 2 つは読み取るソースも生成するものも異なります。

| | `/cost-report` | トークンカード |
|---|---|---|
| ソース | `~/.claude/metrics/costs.jsonl`（ECC の `stop:cost-tracker` フックが書き込む） | 各エージェント自身のセッションログ |
| エージェント | Claude Code | Claude Code、Codex、Gemini CLI、OpenCode |
| 出力 | ターミナルのサマリー、オプションで CSV | リポジトリにコミットされる SVG ファイル |

## 実行するツール

`@tokenchit/cli`（MIT ライセンス）: <https://github.com/iyashjayesh/tokenchit>

**意図的に厳密なバージョンへ固定しています。** `@latest` はレジストリがその時点で配信しているものに解決されます。このツールはローカルのセッションログを読み取るため、将来侵害されたリリースが、誰もレビューしないうちにそれらにアクセスできる状態で実行されてしまいます。バージョンを固定し、固定バージョンの引き上げは意識的に行ってください。

```bash
TOKENCHIT_VERSION=0.10.0
```

固定したアーティファクトを初回実行の前に確認するには、次を実行します。

```bash
npm view @tokenchit/cli@0.10.0 dist.integrity dist.tarball
```

## ワークフロー

1. **最初のダウンロードの前に確認を取る。** `npx` は npm レジストリからパッケージを取得して実行します。これはローカルログを読み取るコードのリモートダウンロードにあたるため、マシンでの初回実行の前にユーザーから明示的な確認を得てください。ユーザーが断った場合は、ここで停止し、何が実行されるはずだったかを伝えます。

2. **ドライランの場合を除き、設定する。** `.tokenchit.json` が存在しない場合は、次を実行します。

   ```bash
   npx -y @tokenchit/cli@0.10.0 init
   ```

   このコマンドは、このマシンでログを持つエージェントを検出して記録します。このファイルはコミットされることを想定しており、認証情報は一切含みません。

   **ユーザーが `--dry-run` を指定した場合は、この手順を完全にスキップし**、`.tokenchit.json` が作成される予定である旨を報告します。設定ファイルを書き込むプレビューはプレビューではありません。

3. **カードを描画する。** 引数なしのコマンドは、設定された出力先に書き込みます。`.tokenchit.json` が別のパスを指定していない限り、出力先は `tokenchit.svg` です。

   ```bash
   npx -y @tokenchit/cli@0.10.0 sync
   ```

   ユーザーが実際に求めたフラグのみを、下記のとおり正確なスペルで追加します。プレースホルダーをコマンドにコピーしないでください。`sync` は認識できない位置引数を拒否せず無視するため、角括弧付きの `[--dry-run]` は無効な引数として CLI に渡り、カードは書き込まれてしまいます。これは求められたことの正反対です。

   | フラグ | 効果 |
   |---|---|
   | `--out <path>` | 設定された出力先以外の場所に書き込む |
   | `--theme auto` \| `light` \| `dark` | カードのテーマ。`auto` は閲覧者のシステムに合わせて変わる |
   | `--dry-run` | 書き込まれる内容を出力し、何も変更しない |

   `sync` はローカルファイルを読み取るだけで、何も送信しません。プロンプト、コード、ファイルの内容はマシンの外に出ず、どのサーバーにも何も送信されません。その外側の npx 呼び出しはレジストリからのダウンロードであり、このワークフローにおけるネットワークアクセスはそれだけです。それに同意を得るのが手順 1 です。

4. **報告して提案する。** 生成された数値（トークン数、API 換算コスト、連続日数、エージェントごとの内訳）と書き込まれたパスを出力します。リポジトリに README があり、まだカードを参照していない場合は、次の追加を提案します。

   ```markdown
   ![tokenchit](./tokenchit.svg)
   ```

   `sync` はリポジトリルートからの相対パスを出力します。Markdown の画像はそれが置かれたファイルからの相対で解決されるため、編集する README に合わせて書き換えてください。`docs/usage.svg` にあるカードは、ルートの README からは `./docs/usage.svg` ですが、`docs/zh-CN/README.md` からは `../usage.svg` になります。出力されたパスをそのままネストした README に貼り付けると、`docs/zh-CN/docs/usage.svg` を指してしまい、表示が壊れます。

   頼まれていない限り、README を編集しないでください。

手順 4 で停止します。公開リーダーボードへの公開は別の `publish` コマンドであり、明示的なオプトインが必要で、このワークフローには含まれません。ユーザーが名前を挙げて求めた場合にのみ実行してください。`unpublish` は、その行とアカウントを再び削除します。

## 出力

SVG のパス、それに含まれる数値、およびそれを参照するための Markdown スニペット。ドライランの場合は、書き込まれるはずだった内容を示し、ディスク上は何も変更しません。

## 注意事項

- Node.js 22 以降が必要です（パッケージは `engines: { node: ">=22" }` を宣言しています）。何もグローバルにはインストールされず、`npx` が実行のたびに固定バージョンを取得します。
- 読み取るのはトークン数とタイムスタンプのみです。
