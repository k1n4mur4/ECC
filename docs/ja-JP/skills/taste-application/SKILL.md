# Taste Application

パイプラインの後半です。**taste-distillation** がリファレンスを計測してスタイルパックにまとめ、このスキルがそのパックに基づいて生成し、結果をカットします。

## 実行と納品の契約

元の実装は `scripts/` に同梱されており、別の `ito-video` チェックアウトは不要です。ローカル処理には `scripts/requirements.txt` をインストールしてください。`scripts/requirements-live.txt` はプロバイダー実行のためだけにインストールします。ライブのアップロード、送信、ダウンロードには、認証情報に加えて明示的な `TASTE_FORGE_ALLOW_LIVE=1` が必要です。これはユーザーが許可した実行に対してのみ設定してください。`--dry-run` は引き続き認証情報なしで動作し、ラベル付きのプレースホルダーを生成します。曖昧なプロバイダーのタイムアウトは、新しい有料ジョブとして再試行されません。再送信が妥当かどうかを判断する前に、プロバイダー側のリクエストを確認してください。

プロバイダー呼び出しなしで、完了済みの既存テイクを使用します。

```bash
python scripts/pipeline.py --genre example --root stylepacks \
  --takes media/take-a.mp4 media/take-b.mp4 --duration 12 --fps 30 \
  --out out/review-v1.mp4
```

`--duration` は**ベストエフォートのカデンス目標**であり、正確な再生時間ではありません。完結したショットの積み重ねによって、編集結果が目標より短くなることも長くなることもあります。アセンブラーは目標に合わせるためにクリップを複製したりパディングを追加したりしません。出力マニフェストには実際の `duration` が保持され、要求秒数と実際の秒数、不足分、超過分、`cadence_target` ポリシーを含む `duration_contract` が追加されます。出力フレーム 1 枚分以上の差は明示的に警告されます。正確な再生時間を保証するモードはありません。正確な尺が必要な場合は、レシートを確認し、納品前にカットを修正するか却下してください。

パイプラインは、実行ごとのグレーディング済みショットファイルを保持します。編集可能な FCPXML と EDL がそれらを参照するためです。出力の衝突は拒否され、タイムラインのエクスポート失敗は報告されます。レンダリングが完了しても、それは保存済みのエディタープロジェクトでもクリエイティブ上の承認でもありません。ライブ編集の前後で、ソースアセットとバージョン管理されたプロジェクトのチェックポイントを保全してください。保存先のパスとダイジェストは、メモリ上のタイムラインのレシートとは別に記録します。

クローン可能な Fal グラフとそのオフライン入力コンパイラーは `workflows/README.md` に記載されています。送信前にブリーフとスタイル指示をコンパイルしてください。つながっていないスキーマフィールドがモデルのプロンプトに影響すると想定してはいけません。有料実行の前に、現行のエンドポイントのフィールドを実際のプロバイダーに対して検証してください。

Blender では、テクスチャ付きのフルソース GLB を使用します。リトポロジーは別名の派生物であり、ソースを置き換えることは決してありません。`blender_prop.py` は明示的な `--width 1920 --height 1080 --fps 30 --receipt receipt.json` をサポートし、パック由来のリムライティングとマテリアルテクスチャを保持します。シーンの保存はレンダリングとは別物です。レシートの状態とパックされた画像を確認してください。

Resolve のオーバーレイには、明示的に選択したバージョン管理済みターゲットから注入したオブジェクトとともに `taste.resolve.apply_placements` を使用します。`source_end_mode` には、そのホストで検証済みの規約を設定してください。Resolve のバージョンをまたいで、ソース終端が包含的であると想定してはいけません。アダプターは、重なり合うエフェクトを保持されたトラックの上に割り当て、すべての配置を即時に、またすべての追加の後にもう一度チェックします。コンポジットの整数値はインストール済みの API と一致している必要があります。検証済みの Studio 21 ホストでは、Screen は 5 であり、従来のビルダーの誤った 22 ではありません。レシートが証明するのはメモリ上の配置のみです。プロジェクトを保存し、チェックポイントを検証し、納品を報告する前に実際にレンダリングされた出力を確認してください。

## 有効化するタイミング

- 「このスタイルで動画を作って」/「パックを適用して」/「この素材を補完して」
- 生成したクリップを、実際の編集リズムを持つ作品へまとめる
- 見た目から 3D 小道具を生成し、動画に戻す
- 完成した作品が実際にリファレンスと一致しているかを検証する

## 役割分担

**モデルは、内容、動き、フレーミング、ライティング構造を提供します。パックは、色とリズムを提供します。** これは好みではなく計測に基づいています。数値については taste-distillation を参照してください。実務上の帰結は次のとおりです。

- 生成プロンプトには**色に関する言葉を一切含めません**。*「Colour: none. Render neutral. Grading is applied afterwards.」* を追加します。
- **2 つの別々のフラグ**を保ちます。`--brief`（何が起こるか: 被写体、アクション、場所）と `--style-steer`（見た目がどうなるか）です。これらを混ぜると、スタイルの言葉がシーンに漏れ（「teal」が青緑色の物体になる）、被写体の言葉がグレードに漏れます。
- モデルは、グローバルなルールよりも**ローカルで検証可能なルール**にはるかによく反応します。「背景は純黒でライティングなし、被写体は白に向かって飛ばす」は機能しますが、「極端なコントラスト」は機能しません。

## ショットではなくテイクを生成する

「カデンスに合わせる」の素朴な解釈は、ショットごとに 1 回生成することです。これは経済的に不合理です。平均 0.78 秒/ショットのリファレンスと、4 秒の下限を持つエンドポイントの組み合わせでは、10 秒の作品に **12 回の呼び出し、10 秒を使うために 48 秒を生成（効率 21%）** が必要になります。しかも、連続して見えるべきものに、無関係な 12 本のクリップがつなぎ合わされます。

編集者は長めのテイクを回し、その内側でカットします。ショットを約 5 秒のテイクにまとめると、**3 回の呼び出し、13 秒の生成、効率 77%** になり、連続するショットは同じ生成から来ているため、実際に互いに属したものになります。

求める形をモデルに伝えないと、カメラを固定したままのゆっくりしたプッシュがレンダリングされ、その内側の 6 回のカットはぎこちなく見えてしまいます。

> 「Filmed as ONE continuous take with no hard cuts inside it. It will be cut into
> 6 pieces of roughly 0.8s in the edit, so the framing, subject and light must
> keep changing throughout — any 0.8s window has to stand alone as its own shot.」

## カットのルール

- **再エンコードし、ストリームコピーは決してしない。** ストリームコピーはキーフレームでしかカットできず、平均ショット長 0.78 秒ではすべての境界が最寄りの GOP に丸められ、パイプラインが守るべきまさにそのものを破壊します。
- **既存の素材を補完するときは、その素材自身のショット境界を使う。** ベース動画を連続した断片に切り分けて順に再生すると、元の動画を再構成するだけで、すべての「カット」がショットの途中に落ちて見えなくなります。計測では、20 ショットのアセンブリで検出されたカットは 12 回だけでした。実際の境界を検出し、N 個おきに取ることで、連続する選択が必ず不連続になるようにします。これにより、カットの計測値は目標 0.78 秒に対して 1.29 秒から 0.83 秒に改善しました。
- **ショット長は平均ではなく、リファレンスの分布からサンプリングする。** そうすることで、カットはリズムのばらつきを引き継ぎ、均一なクリップに平坦化されません。

## グレーディングのルール

- **クリップがあるなら、焼き込み済み LUT よりも直接計測が勝る。** 計測し、その L\* の CDF に合わせ、ゾーンのクロマを適用します。`grade_clip_direct` は、コントラスト 34.7 に対して 34.0、MAE 1.58 に達しました。
- **クリップのヒストグラムがリファレンスと似ていない場合は、CDF マッチングではなくアンカーを使う。** 黒が 68% の生成クリップを、雑多なリファレンスのヒストグラムに無理やり合わせると、背景全体が黒から持ち上がりました。MAE とコントラストはどちらも優秀に見えたまま、背景の保持率は 26.0%（CDF）対 69.0%（アンカー）まで低下しました。デフォルトではアンカー付きのトーンを使用してください。
- **バッチサイズが重要。** 48 フレームを一度にグレーディングするとプロセスが OOM で強制終了されました。6 なら安全です。

## 復元した fal プラットフォームの挙動

これらの観察結果とエンドポイントの例は、復元したワークフローから得られたものです。現行のエンドポイントのメタデータを再確認してください。将来のあらゆるプロバイダーバージョンについての保証ではありません。同梱のグラフテンプレートには、生成オーディオの明示的な制御を含む、別途検証済みのワークフロー入力が記録されています。

これらは発見するまでに実際に時間がかかりました。グラフを設計する前に確認してください。

| 制限 | 詳細 |
|---|---|
| **3D レンダラーが一切ない** | fal にあるのは `image-to-3d`、`text-to-3d`、`3d-to-3d` だけです。`3d-to-3d` エンドポイントはすべて別のメッシュを出力します。`3d-to-image`/`3d-to-video` カテゴリは存在しないため、生成した GLB を fal の動画グラフに再投入することは**できません**。ローカルでレンダリングし、その後 `fal-ai/ffmpeg-api/images-to-video` を使用してください。 |
| **compose はオーバーレイできない** | `fal-ai/ffmpeg-api/compose` は 2 本目のトラックを *「Multiple video tracks are not supported」* で拒否します。しかも `image` トラックも動画トラックとして数えます。動画トラックは 1 本しかシーケンスできません。**ffmpeg でローカルに合成してください。** |
| **compose のキーフレームはミリ秒** | レスポンスのどこにもそう書かれていません。秒で送信した実行は受理され、1000 倍短い動画が返ってきます。 |
| **extract-frame は first/middle/last のみ** | 任意のタイムスタンプは指定できません。3 つを、3 枚の別々のコンディショニング画像として使用してください。 |
| **DAG にループも文字列連結もない** | ショットごとのファンアウトは、ノードごとに手作業で記述するか、ローカルで処理する必要があります。 |
| **Kling 3.0 には reference-to-video がない** | v3 系列は text/image/motion-control のみです。reference-to-video は `o3` 系列にあります: `fal-ai/kling-video/o3/pro/reference-to-video`。 |
| **プレフィックスは統一されていない** | `bytedance/*`、`tripo3d/*`、`meshy/*`、`minimax/*`、`openai/*` には `fal-ai/` プレフィックスが**付きません**。`kling-video`、`veo3.1`、`flux-*`、`hunyuan-3d`、`ffmpeg-api` は付きます。 |

### エンドポイントの選択

| スロット | ベスト | コストパフォーマンスの代替 |
|---|---|---|
| reference→video | `bytedance/seedance-2.5/reference-to-video`（720p で約 $0.473/秒） | `fal-ai/kling-video/o3/pro/reference-to-video`（約 $0.112/秒） |
| image→3D | `fal-ai/hunyuan-3d/v3.1/pro/image-to-3d`（$0.375、最大 8 ビュー） | `tripo3d/h3.1/image-to-3d`（$0.20） |
| text→3D | `fal-ai/hunyuan-3d/v3.1/pro/text-to-3d` | `tripo3d/h3.1/text-to-3d` |
| リトポロジー | `fal-ai/hunyuan-3d/v3.1/smart-topology`（$0.75） | `tripo3d/tripo/remesh`（約 75 倍安い） |
| パーツ分割 | `fal-ai/hunyuan-3d/v3.1/part`（FBX のみ） | `tripo3d/tripo/segment` |
| text→image | `fal-ai/nano-banana-pro`（定額 $0.15） | `fal-ai/flux-2-pro`（$0.03/MP） |

Seedance は、同じ 5 秒で Kling o3 の約 4 倍の価格です。その価格に見合うのはマルチリファレンスの忠実度（画像/動画/音声の混合リファレンスを最大 50 件）であり、1 枚の静止画をコンディショニングに使う場合には見合いません。

モデル ID と価格は変動します。いずれかを約束する前に、fal.ai/models で確認してください。

## 3D ブランチ

```bash
python mint3d.py --genre <name> --from-stills 4 --retopo --render
python mint3d.py --genre <name> --prompt "a cracked chrome visor" --render
```

- **まずクリーンなプレートを生成し、リファレンスの静止画から流用しない。** エンドポイントが明示している入力要件は、シンプルな背景、単一のオブジェクト、オブジェクトがフレームの 50% 超、というものです。リファレンスリールはその正反対で、コラージュ、ワイドショット、複数の被写体、焼き込みグラフィックスを含み、ノイズ状のでたらめな造形を生みます。テキスト → 単一オブジェクトのプレート → メッシュは約 $0.15 の追加コストで、使えるメッシュと破棄されるメッシュの差になります。
- **マルチビューはリストではなく、アングルごとの名前付きフィールド。** `input_image_url`（正面、必須）に続いて、`back_image_url`、`left_image_url`、`right_image_url`、`left_front_image_url`、`right_front_image_url`、`top_image_url`、`bottom_image_url` です。`input_image_urls` や `multi_view` フラグは存在しません。これらを自作すると、見かけ上は動作したまま、すべての生成（mint）がシングルビューに劣化します。モデルはラベルを信頼するため、誤ったアングルのラベルはビューを省略するよりも悪い結果になります。
- **GLB は位置ではなくキーで指定する。** レスポンスには `model_glb` と並んで `thumbnail` PNG と `model_urls` ブロックが含まれます。最初の URL を取る方法は、キーの順序が変わるまでしか通用せず、プレビュー PNG も問題なくダウンロードできてしまうため、Blender が開くのを拒否するまで何も失敗しません。
- **PBR マップを要求する。** なければ、メッシュは塗装された段ボールのようなライティングになります。
- **誰かが編集やリグ付けをするなら、リトポロジーを行う。** 生成されたメッシュは高密度で、乱雑です。
- **ローカルでレンダリングしてループを閉じる。** ターンテーブルがフレームになれば、それは素材であり、下流のすべてのステージが素材を扱えます。グレーディングし、カットし、エレメントとしてスクリーン合成し、あるいはコンディショニングのリファレンスとしてアップロードできます。バイナリが PATH にあるときは Blender を使用してください。ヘッドレスの GL コンテキストはコンテナで最も欠けがちなものであり、ワークステーションでしか動かないレンダラーはパイプラインの一部ではないため、依存の少ないソフトウェアラスタライザーをデフォルトとして保持してください。

## 検証してから信じる

他のすべてのステージは結果を主張します。それを確認し、平均や分散といった統計量だけでなく、**分布の形**も確認してください。

- `background` — フレームのうち L\*10 未満の占有率を、**パック**の数値と比較します。ソースクリップではなくリファレンスと比較してください。黒が 68% の生成ソースは、24〜55% の帯にあるどのリファレンスよりも黒いため、「ソースの黒を保持する」は誤ったことを要求し、持ち上がったグレードも同様に容認してしまいます。
- `chroma_mae` — ゾーンごとの a\*/b\* 誤差を、**中央値**を使って算出します（パックのターゲットが計測された方法に合わせます。ここで平均を使うと、歪みに敏感な統計量を頑健な統計量と比較することになり、定義の不一致を誤差として報告してしまいます）。
- `contrast` / `black_point` / `white_point`
- `banding` — 占有されたビンの*間にある*空の L\* ヒストグラムビン。空ビンの総数を数える方法は機能しません。正当に暗いクリップはハイライト側に空ビンを持つためです。
- `cadence` — 検出された平均ショット長とリファレンスの平均ショット長の比較。

**単位の罠**に注意してください。OpenCV は dtype によって Lab の規約を変えます。float32 では L\* は 0–100 で a\*/b\* は符号付きですが、uint8 では L\* は 0–255 で a\*/b\* は +128 のオフセット付きです。これらを混在させると、クロマ誤差が数百と報告されます。

## フルチェーン

```bash
python pipeline.py --genre <name> --refs a.mov b.mov \
  --brief "what happens" --duration 12 \
  --base-video existing.mp4 --out out/FINAL.mp4
```

mint → distill →（mint3d）→ apply → forge → verify。ステージ 1〜3 はキャッシュされるため、ブリーフを繰り返し調整しても何も再計測されません。`--dry-run` はすべてのネットワーク呼び出しをスタブ化します。プラン、プロンプト、トラックレイアウト、マニフェストは、それでもすべて実行されます。

## アンチパターン

| やってはいけないこと | 理由 |
|---|---|
| ショットごとに 1 回生成する | 効率 21%、無関係な 12 本のクリップ |
| プロンプトに色を入れる | 機能しないことが計測されており、LUT が求めるニュートラルなベースから遠ざける |
| カットをストリームコピーする | キーフレームのみの境界がサブ秒のリズムを破壊する |
| ベース動画を連続してカットする | 元の動画を再構成してしまい、すべてのカットが見えなくなる |
| compose でのオーバーレイを当てにする | できない。2 本目のトラックを拒否する |
| compose に秒を送る | 黙って 1000 倍短くなる |
| MAE だけで出荷する | 背景占有率のチェックを追加する |

## 借用した素材にはキャプチャアプリの UI が写り込む

納品されたカットで見つかった最悪の欠陥は、完成した動画に他人のいいねボタン、視聴回数カウンター、コメントの吹き出しが入ったまま出荷されたことでした。ベース素材が画面収録で、何もそれらをクロップしていなかったためです。

**`content_mask` はこれを解決せず、そのバウンディングボックスは事態を悪化させます。** 時間方向の分散はインターフェースの UI クローム（操作用の UI 要素）を残します。UI クロームは*アニメーションする*（ハートが脈打ち、カウンターが進む）ため、マスクはそれを動いているコンテンツとして印付けるからです。3 つのリファレンスで計測したところ、インターフェースが右側のマージンにはっきり写っているにもかかわらず、マスクの bbox は毎回幅の 100% を保持しました。

分離する手がかりは分散ではなく、時間方向の**中央値**です。素材は動くため、多数のフレームの中央値は平均化されてほとんどエッジエネルギーのないぼやけた平均像になります。一方、UI クロームは固定座標にあるため、そのエッジは無傷で残ります。中央値フレームに対する Sobel エネルギーは、UI クロームでは点灯し、コンテンツでは静かになります。計測では、あるリファレンスで右端の列が 0.23 に対し内部背景が 0.03、別のリファレンスでは 0.31 に対し 0.15 でした。

それぞれ 1 サイクルずつ費やした実装上の 2 つの詳細があります。

- **端から内側へ向かって削るのではなく、外側の各帯にある最も内側の外れ値の先まで削る。** 現在の行のエッジエネルギーが高い間だけ内側へ進む方法は、即座に止まります。最も外側の行はレターボックスであり、平坦な黒でエッジエネルギーがゼロで、UI クロームはその*内側*の幅の 90〜95% の位置にあるためです。素朴な実装ではフレームの 1% しか削れず、いいねボタンはショット内に残りました。
- **縦長のソースを横長のカットに入れるときは、パディングではなくカバーでスケールする。** 9:16（UI のクロップ後はさらに細くなる）を 16:9 にパディングすると、フレームの約 60% が黒帯になり、あるショットはほとんど空の長方形になり、黒帯は純黒であるため背景メトリクスも汚染しました。カバーすると両側が失われますが、中央構図の素材にとってはそれが正しいトレードオフです。

## オーバーレイプレートはウォッシュではなくエレメントである

グローのプレートは構造上、約 4% しか覆いません。それをフレームサイズで合成すると、ショットの中央に置かれた小さな明るい点になり、ステッカーのように見えます。実際に、納品されたカットで説明のつかない色付きの染みとして目に見えていました。

- **まず各プレートをそのアルファのバウンディングボックスまで絞り込む。** これによりカバレッジは約 4% から 15〜35% に上がり、エレメントがたまたまソースフレームに占めていた割合を引き継ぐのではなく、サイズの制御が呼び出し側に渡されます。
- **カバレッジに基づいてウォッシュとエレメントを選ぶ。** 拡散したプレート（絞り込み後に 10% 未満）は、低い不透明度でフレーム全体に引き伸ばすとうまく機能します。集中したプレートは、フレーム幅の 35〜70% にスケールして配置したいものです。
- **ショットごとに、シード付き RNG から配置、スケール、回転を変化させる。** そうすればカットは再現可能なまま、スタンプされた 2 つのショットが同じ印を共有することはありません。N ショットおきに 1 つのプレートが 1 か所に置かれると、透かしのように見えます。
- **エレメントのジオメトリは ffmpeg の式ではなく Python で解決する。** `pad()` は負のオフセットを拒否し、入力サイズより小さくはパディングできないため、大きすぎるエレメントやフレーム外のエレメントはフィルターグラフ全体を失敗させます。

## 下流への引き継ぎ（Resolve / Blender）

**mp4 と並べて、必ず編集可能なタイムラインを納品する。** 平坦化された動画は鑑賞用のコピーであり、カラリストが作業できない唯一のものです。すべてのカットが焼き込まれ、ショットはもはや分離できません。`forge.py` は、グレーディング済みの個々のショットファイルを参照する FCPXML 1.9 と CMX3600 EDL を書き出すため、作品は再カットと再グレーディングが可能なタイムラインとして届きます。

エクスポートは想定せずに検証してください。asset-clip のオフセットが先行する長さの累積和に等しいこと（ギャップがない）、すべての `ref` が宣言済みのアセットに解決されること、すべての `media-rep src` がディスク上に存在すること、そして合計が mp4 と一致することを確認します。インポートはできるのにずれていくタイムラインは、大きな音を立てて失敗するタイムラインよりも悪いものです。

黙って作業を台無しにするものが 2 つあります。

- **プロジェクトのフレームレートはインポート前に設定する。** Resolve は最初のタイムライン作成時にタイムラインの fps をロックし、カデンスを黙ってコンフォームします。平均ショット長が 1 秒未満では、そのコンフォームは目に見えます。
- **納品されるショットはすでにグレーディング済みである。** `look.cube` は新しい素材とマッチングのための*正規化*用 LUT です。供給されたショットに適用すると二重にグレーディングされます。ノード 1 に置き、その前には何も置かず、補正はその後に行います。

計測済みのターゲットを記載した引き継ぎドキュメントを同梱します（`scripts/HANDOFF-TEMPLATE.md` は記入済みの例です）。ゾーンのクロマ表、**リズムのばらつき**を含むカデンス分布（平均には合わせてもばらつきに合わせない編集者は、まったく違って見えるものを作ります）、そして明示的な「やってはいけないこと」リストを含めてください。

Blender では、`scripts/blender_prop.py` がパックからライティングを導出します。透明フィルムの黒いワールド（レンダリングをキーイングなしで合成できる）、キーとリム（キーだけではシルエットが黒の中で死ぬ）、そしてパックのピーククロマゾーンから Lab→リニア sRGB で変換したリムカラー（小道具が、素材がグレーディングされているのと同じ色かぶりを拾う）です。**ビュートランスフォームは AgX/Filmic ではなく Standard にし、Blender 内ではグレーディングしない。** AgX は LUT がピクセルを見る前に独自のトーンカーブを適用するため、二重にグレーディングすると効果が累積します。

## 同梱コード

このスキルの `scripts/` は疑似コードではなく、動作する実装です。プロジェクト固有の前提はありません。任意のリファレンス動画を指定すれば、パックを生成します。

```bash
pip install -r scripts/requirements.txt
export FAL_KEY=...            # fal を呼び出すステージでのみ必要
```

すべてのネットワーク呼び出しは `TASTE_FORGE_DRY_RUN=1` または `--dry-run` の下でスタブ化されるため、プラン、プロンプト、トラックレイアウト、マニフェストを、費用をかけずに確認できます。
