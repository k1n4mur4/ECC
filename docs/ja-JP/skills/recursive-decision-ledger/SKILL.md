# 再帰的判断台帳

ユーザーが繰り返しのロールアウトや「Prime Gauss」スタイルの再帰的プロンプティングによって、より深い計算を強制しようとしているときにこのスキルを使用します。有用な部分である、繰り返しの試行、過去の記録、最新の情報、明示的なマークは残します。危険な部分である、ループが確実性を証明するかのように扱うことは取り除きます。

## 台帳の規約

すべてのロールアウトで次を記録します。

- ロールアウト ID とタイムスタンプ
- 以前に採用された勝者と以前のウォッチリスト
- 取り込んだ新しい情報
- 探索空間のサイズ
- 使用したモデルファミリーまたはヒューリスティック
- 試行回数と有効試行回数
- 上位の候補
- 判断マーク
- 以前の台帳に対する整合性マーク
- 昇格ゲートの結果

追記専用の台帳には JSONL を、人間向けのサマリーには Markdown を使うのが望ましいです。

## ロールアウトループ

1. 以前の台帳を読み込む。
2. 時間ステップ 0 で新しい情報を取得する。
3. 範囲を限定した探索を実行する。
4. 各候補にマークを付ける: accept、watch、reject、decay watch、needs replay のいずれか。
5. 勝者を以前の勝者および直近のマーク済みロールアウトと比較する。
6. ドリフト、テールリスク、古いデータ、リプレイの失敗によって以前のマークが無効になった場合は、候補を格下げする。
7. サマリーを作成する前に成果物（台帳やログなど）を追記する。

## 整合性マーク

簡潔な整合性マークを含めます。

```text
Ensemble matches prior winner: true
Recursive matches prior winner: false
Latest rollout match: true
Live promotion allowed: false
Reason: replay and freshness gates not satisfied
```

## 昇格ルール

トレード、資本配分、本番デプロイ、マイグレーション、破壊的操作では、再帰的な確信度は承認ではありません。

ユーザーがライブでの操作を明示的に承認し、かつリポジトリ／サービス側のゲートがそれをサポートしている場合を除き、ペーパートレード、ドライラン、読み取り専用、プレビュー、またはステージングモードを既定とします。

昇格するのは次の場合のみです。

- 選択した指標で、候補が以前に採用された勝者を上回っている
- 正しさとリプレイのチェックに合格している
- リスク上限が明示されている
- 証拠が永続的に残っている
- 必要な場合、ユーザーがライブステップを承認している

## サマリーの形式

演出ではなく、判断から書き始めます。

```text
Rollout 15 complete. The prior winner still holds, but edge deteriorated 17%.
Status: watch, not live. Next gate: 20 replay fills with fresh orderbook age
below threshold.
```
