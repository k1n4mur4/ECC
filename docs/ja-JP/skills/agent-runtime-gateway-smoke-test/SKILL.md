# エージェントランタイム ゲートウェイ スモークテスト

エージェントタスクがリモートサンドボックスで実行され、ゲートウェイ経由でローカル API にコールバックする場合に、このワークフローを使用します。接続済みのツールや本番の非公開データに頼ることなく、経路全体を検証します。

## 有効化するタイミング

- ローカルのエージェント API でエンドツーエンドのランタイム確認が必要な場合。
- ディスパッチ後にタスクが停止し、ゲートウェイまたはトンネルに到達できない可能性がある場合。
- エージェントのテストのために、Web アプリを一時的にローカル API に向けている場合。
- 以前のテストにより、Web アプリが停止済みの API を指したままになっている場合。

## 必要な入力

- API と Web アプリを起動するための、リポジトリ相対パスで書かれた手順。
- ゲートウェイのルートパスと、匿名アクセス時に期待されるレスポンス。
- 分離されたテスト用エージェント、ツールを使わないプロンプト、およびその正確な期待回答。
- タスクのステータスを確認し、コールバックがローカル API に到達したことを確認する手段。
- プロジェクトの通常のシークレットストアを通じて提供されるプロバイダーの認証情報。共有ドキュメントにはプロバイダー名を記載し、認証情報の値をスキルやテストレポートにコピーしないでください。

これらの入力が揃わない場合は、エンドポイントを推測したり実際のアカウントを使用したりせず、不足している入力を報告してください。

## 認可とクリーンアップ

選択したトンネルプロバイダー経由でローカルのテスト API を公開すること、テストタスクをディスパッチすること、および Web アプリのルートを一時的に変更することについて、認可を得ていることを確認してください。分離されたローカルの Web アプリまたはテストデプロイを使用し、このスモークテストの一環として共有の本番アプリを切り替えないでください。トンネルへのアクセスは、必要な認証付きルートに限定してください。

ルートを変更する前に、クリーンアップ処理を設定してください。成功、エラー、タイムアウト、中断、キャンセルのいずれの場合も、記録しておいた接続先を復元し、ヘルスを確認してから API とトンネルを停止します。このテストで作成したプロセス ID またはリソースのみを追跡してください。復元に失敗した場合は直ちに報告し、復旧に必要な証拠を保持してください。成功したと報告してはいけません。

## スモークテスト

1. **元のルートを記録して確認する。** Web アプリの現在の API 接続先を控え、正常であることを確認します。この値は復元用にローカルで保持します。テスト用エージェントとデータが実ユーザーから分離されていることを確認します。
2. **ローカル API とトンネルを起動する。** テスト全体を通じて両方を稼働させ続けられるプロセスマネージャーを使用します。API のヘルスを確認します。ゲートウェイのルートに匿名でプローブを送り、ドキュメントに記載された認証レスポンス（通常は `401` または `403`）を確認します。プローブがローカル API のログに現れることを確認してください。エッジのレスポンスだけでは API に到達したことの証明になりません。
3. **両方のチェックが通ってから Web アプリを切り替える。** Web アプリからのリクエストがローカル API に到達することを確認します。Web サーバーの再起動や設定のリロードの後は、ルートを再度確認します。
4. **ツールを使わないタスクを 1 つ実行する。** 正確な期待回答がある短いプロンプトを使用します。リモートサンドボックスがローカルゲートウェイを呼び出したこと、タスクが終了状態に到達したこと、返された回答が一致することを確認します。キュー待ちや実行中のタスクは合格ではありません。
5. **元のルートを復元する。** Web アプリを記録しておいた API 接続先に戻し、その接続先と代表的なページの読み込みを確認してから、テスト用の API とトンネルを停止します。復元に失敗した場合は、壊れたルートを直ちに報告します。

チェックの例（値はプロジェクトから提供されます）:

```sh
curl --silent --show-error --output /dev/null --write-out '%{http_code}\n' "$LOCAL_API_HEALTH_URL"
curl --silent --show-error --output /dev/null --write-out '%{http_code}\n' "$PUBLIC_GATEWAY_PROBE_URL"
```

1 つ目のコマンドはプロジェクトの正常ステータスを返すはずです。2 つ目はドキュメントに記載された匿名認証ステータスを返し、**かつ**ローカル API のログに現れるはずです。どちらの URL にも認証情報を含めないでください。

## 接続済みツールのフォローアップ

ツールを使わないタスクが合格した後にのみ、別のテストを実行します。明示的なテスト用接続と権限付与を使用します。接続の有無と付与されたアクションは、別々の事実として報告してください。アクション検索の結果が空だからといって、アプリが接続されていないと推測しないでください。スモークテストとして、実際のアカウントに対する書き込みアクションを実行してはいけません。

## 失敗時の対応

| 観察された事象 | 次のチェック |
| --- | --- |
| Web ページは読み込まれるが API リクエストが失敗する | 設定済みの API 接続先をリッスン中のプロセスと比較し、元のルートを復元する。 |
| ゲートウェイプローブが接続エラーまたは `404` になる | タスクをディスパッチする前に、トンネルの有効期間、ルートパス、ローカル API のヘルスを確認する。 |
| ゲートウェイプローブが `401` または `403` を返すが、ローカルログにエントリがない | レスポンスはトンネルのエッジから返されている可能性がある。コールバック経路を検証する。 |
| タスクがキュー待ちまたは実行中のままになる | 別のディスパッチャーがタスクを取得していないか、サンドボックスがローカルゲートウェイに到達したかを確認する。 |
| タスクが誤った回答で終了する | タスクのステータスと機密情報をマスクしたエラーを記録する。スモークテストが成功したとは言わない。 |

## 出力フォーマット

次の内容を含む簡潔なレポートを返します。

- ローカル API は正常か: はい / いいえ
- ゲートウェイプローブのステータスとローカルログでの確認
- リモートコールバックを観測したか: はい / いいえ
- ツールを使わないタスクの終了ステータスと、正確な回答が一致したか
- 元の Web API ルートを復元し、正常であるか: はい / いいえ
- 未解決のブロッカーまたは次のアクション（ある場合は 1 つ）

アカウントの詳細、認証情報の値、個人用のパス、公開トンネルの URL、非公開の生ログはレポートに含めないでください。元のオペレーターノートはローカルに保管してください。
