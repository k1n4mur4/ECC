# Taste Distillation

この単体スキルは実装を `scripts/` に同梱しています。その後の生成テイクまたはローカルテイクの編集には
`taste-application` を使用してください。名前付きのジャンルごとに、それぞれ別のパックとして保持してください。
Flash Ethereal で計測した値を、Fluid Sketch や 3D Cyber Glitch に黙って流用してはいけません。
計測結果としてのゼロは有効なデータです。フィールドが存在しない状態とは区別してください。

ローカルの依存関係は `scripts/requirements.txt` にあります。別途許可されたプロバイダー作業には、
`scripts/requirements-live.txt`、認証情報、および明示的な `TASTE_FORGE_ALLOW_LIVE=1` も必要です。
`--dry-run` は認証情報を読み取らず、ジョブも送信しません。ローカルのエンドポイント名からワークフローが保存されたと
推測してはいけません。プロバイダー側の実際のワークフローまたはリクエストの証跡を使用してください。

リファレンス動画を **スタイルパック** に変換します。スタイルパックとは、後続のステージが決定論的に利用する
計測結果とアセットのフォルダーです。

## 有効化するタイミング

- 「これらのクリップのルックを捉えたい」/「雰囲気を蒸留したい」/「再現可能にしたい」
- ユーザーがリファレンス映像を持っており、LUT、グレード、または一致するペーシングを求めている
- ジャンルごとに区切ったルックのライブラリを構築する
- 本来なら「プロンプトでスタイルを説明する」と答えてしまいそうなあらゆる依頼

## 中核となる発見

**プロンプトではグレードを実現できません。計測なら実現できます。**

実際の映像での計測結果: 色の指示を段階的に強めた3回の有料生成では、ミッドトーンの a\* は、目標値 **+24.9** に対して +1.9 → +2.8 → +0.3 と推移し、
コントラストも目標の **34.7** に対して約19から動きませんでした。
計測したパックを同じ映像に適用すると、1回の決定論的な処理で、無料のまま、クロマ MAE **1.88**、コントラスト **33.7** に到達しました。

したがって役割分担は次のとおりです。**モデルはコンテンツ、動き、ライティングの構造を担い、パックがルックを担います。**
生成プロンプト内の色に関する言葉は役に立たないどころか有害です。費用がかかるうえ、LUT が前提とするニュートラルなベースから
レンダリングを遠ざけてしまいます。プロンプトには明示的に次のように書いてください。*「Colour: none. Render neutral. Grading is applied afterwards.」*

## パックの内容

```
stylepacks/<genre>/
  grade.json      計測したカラー統計（下記参照）
  cadence.json    検出したすべてのショット境界と、そこから導出した分布
  look.cube       33^3 LUT。Resolve のノード LUT としてそのままドラッグ可能
  spec.json       VLM による説明。計測結果に基づく
  grounding.txt   VLM に与えた計測済みの事実
  stills/         最長ショットのフル解像度フレーム（コンディショニング画像）
  plates/         黒地に抜き出したスクリーンブレンド用オーバーレイ要素
  props/          生成した GLB メッシュ
  pack.json       マニフェスト
```

## 実行方法

```bash
python mint.py --genre <name> --refs a.mov b.mov c.mov     # オフライン、API キー不要
python distill.py --genre <name>                            # VLM 呼び出しは1回
```

`mint.py` は純粋な数値解析であり、ネットワークもキーも不要で決定論的です。そのため、パックはバックアップしなくても再生成できます。

## 重要な計測項目

### クロマは全体ではなく輝度ゾーンごとに測る

色のアイデンティティは、たいてい **1つの輝度帯** に存在します。全体の a\*/b\* オフセットでは、数学的にスプリットトーニングを表現できません。
ゾーン（`L* edges [0,15,35,55,75,100]`）ごとにクロマを計測してください。

実際のシグネチャの例: L\*25 にバイオレット（a\* +24.9、b\* −17.5）があり、両端はほぼニュートラルです。
最も暗いゾーンと最も明るいゾーンだけを報告すると、これを「均一なカラーキャスト」と呼んでしまいます。
**必ずカーブ全体を出力してください。**

### 平均と標準偏差ではなく、中央値と MAD を使う

実際のリファレンスセットではクロマが強く右に歪みます。ある実測のリールでは、ミッドトーンのクロマは平均が 36.9、中央値が 17.5 でした。
そのため平均ベースの LUT は、素材が必要とする約3倍の強さで色を押し出していました。

### コントラストは白と黒の差ではなく std(L\*) で測る

白と黒の差は、ほぼあらゆる実映像で約100になり、何も区別できません。

### 背景の占有率は一級の統計量である

L\*10 未満のピクセルの占有率を記録してください。分布のどのモーメントもこれを捉えられません。
クリップは平均、標準偏差、クロマが正しくても、黒がグレーに持ち上がっている可能性があります。
まさにこの理由で、あるグレードは MAE 1.88 / コントラスト 33.7 と評価されながら、実際のフレームは黒が持ち上がって濁った紫色になっていました。

### 計測の前にインターフェースをマスクする

画面録画のリファレンスには、レターボックスのバー、ステータスバー、いいねアイコン、キャプションテキストといった静的な要素が含まれます。
これらはすべて、ルックであるかのように統計へ混入します。黒いバーはシャドウの重みを膨らませ、赤いハートは a\* をマゼンタ寄りに歪めます。
**時間的な分散によって、これらをきれいに分離できます。** 映像は動き、インターフェースは動かないためです。
そのため手作業で調整したクロップは不要です。実際の素材では、約65%のピクセルが残ります。

### カデンスには適応的なしきい値が必要

適切なコンテンツ検出のしきい値は素材によって異なります。コントラストの高いアクションのリファレンスは、しきい値30でも十分に検出できるほどはっきりカットされますが、
ムーディーなリファレンスではカットがそのしきい値の下に隠れてしまいます。しきい値を降順にスイープし、最も感度の高い設定で検出されるショットの
90%以上を回復できる **最も高い** しきい値を採用してください。これにより、ノイズよりも実際のカットを優先する方向に寄せられます。
カット率が異常に高くなる（>100/分）しきい値は却下してください。連続したカメラの動きは、毎フレーム検出器を誤作動させます。

スイープ全体は、共有した `StatsManager` を使って **1回のデコードパス** で実行してください。
しきい値ごとに再デコードする素朴な実装では、60fps のソースの場合、数秒と数分の差になります。

## オーバーレイプレート: スクリーンショットではなくアセット

スチルはフレーム全体です。それを合成しても、2枚目の画像を上に重ねるだけです。
**プレート** とは、リファレンスのグラフィックの語彙（フレア、ストリーク、グリッチの断片）を黒地に抜き出したもので、
キーイングなしでスクリーンブレンドできます。

実際の素材で遭遇した、2つの落とし穴があります。

1. **絶対値のしきい値は失敗します。** 明るいリファレンスでは、`L>55 AND chroma>12` の選択でフレームの約90%が選ばれてしまい、
   「プレート」は認識可能な顔を含む画像そのものになります。**パーセンタイル**（上位約3%）で選択し、
   **フレームの約22%を超えて覆うプレートはすべて却下してください。**
2. **明るさではなく、分離度でランク付けします。** 「明るく彩度の高いピクセルの割合」では、色あせたフレームが上位になり、
   本来のシグネチャである強烈なフレアが1つだけある黒いフレームは下位になります。
   `p99.5(energy) / median(energy)` でスコアリングしてください。

スコアリングの前にもマスクしてください。焼き込まれたタイポグラフィは明るく、彩度が高く、コントラストも高いため、
マスクなしで実行すると、他人のタイトルカードの完璧なプレートが得られてしまいます。

## VLM のグラウンディング

説明を求める前に、計測結果をシステムプロンプトに与えてください。グラウンディングなしでは、VLM は a\* が +24.9 のカラーキャストがある映像に対して
「明らかなカラーグレーディングなし、ニュートラル」と報告します。グラウンディングすれば、キャストを正しく説明し、
セカンダリーアクセントも独自に推論します。

曖昧な語（`varied`、`mixed`、`dynamic`、`some`、`often`、`neutral`、`or`）は禁止してください。
モデルは「変化に富んだライティング」をレンダリングできません。**この禁止はプロンプトだけでなく、コードで強制してください。**
3回の実行につき1回ほどの割合で違反されていました。フィールドごとに再質問し、N回試行した後は失敗とせず、最も曖昧さの少ない回答を残します。

ユーザーに伝えておくべき注意点があります。仕様が計測結果に基づいて作られている以上、それはもはや計測結果の独立した検証にはなりません。

## LUT ベイクの落とし穴

- LUT が表現できるのは **ピクセル単位の RGB 関数** だけです。分布に依存するもの（ヒストグラムマッチング、パーセンタイルアンカー）は、
  ベイクの *前に* 定数に落とし込む必要があります。そうしないと、映像ではなく一様な LUT グリッドを黙って計測してしまいます。
- `cv2.cvtColor(LAB2RGB)` は **内部でクランプします**。そのため、これを使った色域外テストは 0% と報告します。
  Lab からリニア sRGB への変換は手作業で行ってください。実測では 83.3% が色域外でした。
- クロマ転送はアフィンではなくオフセットにします。アフィンはソースの σ で除算するため行き過ぎます。実際の映像では、目標 −17.5 に対して b\* が +11.6 に反転しました。
  オフセットにすると MAE は 6.23 から 2.13 になりました。
- ガマット圧縮は、同一の MAE に対して実行時間が3.8倍かかりました。オプトインにしてください。

## アンチパターン

| やってはいけないこと | 理由 |
|---|---|
| 合成したテスト映像に対してチューニングする | 1つのプロジェクトで4回の誤った結論を招き、実映像がそのすべてを覆した |
| MAE だけを信頼する | 1.88 の MAE は、明らかに破綻したフレームでも成功のように見えた |
| クロマに平均/標準偏差を使う | 右に歪んでおり、約3倍強く押し出してしまう |
| 両端のゾーンだけを比較する | 両端は構造上ほぼニュートラルになる |
| ルックを説明して終わる | 仕様はコンテンツと構造のためのもの。色はパックが担う |

## 引き継ぎ

パックがインターフェースです。パックができたら、**taste-application** スキルを使ってそれに対して生成・組み立てを行うか、
`look.cube` をカラリストに直接渡してください。

## 同梱コード

このスキルの `scripts/` は疑似コードではなく、動作する実装です。プロジェクト固有の前提はありません。
任意のリファレンス動画を指定すれば、パックを生成します。

```bash
pip install -r scripts/requirements.txt
export FAL_KEY=...            # fal を呼び出すステージでのみ必要
```

すべてのネットワーク呼び出しは、`TASTE_FORGE_DRY_RUN=1` または `--dry-run` のもとでスタブ化されます。
そのため、費用をかけずに、計画、プロンプト、トラックレイアウト、マニフェストを確認できます。
