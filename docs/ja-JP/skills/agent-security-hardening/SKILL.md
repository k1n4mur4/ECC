# エージェントセキュリティ強化

エージェントが信頼できないデータをファイルシステム、ネットワーク、メモリ、ツールのアクションに変換する境界を強化します。レビュー対象のフレームワークに対して具体的な制御とテストを作成してください。強制（実施）されていることを示す証拠のないチェックリストは不完全です。

## 重要事項

- モデル出力、取得したコンテンツ、ツール出力、メモリ、エージェント間メッセージを信頼できない入力として扱う。
- 外部連携はデフォルトで読み取り専用とし、書き込み権限は個別に付与する。
- 上流のプロンプトやスキーマがすでに値を検証していても、アクションの境界で検証する。
- 識別情報、宛先、所有権、またはコンテインメント（封じ込め）を証明できない場合は、副作用が発生する前にフェイルクローズする。
- 削除、公開、認証情報のローテーション、その他の不可逆なアクションの前に、実際のツールのエントリポイントで、認証済みプリンシパルがその正確な操作とリソーススコープに対して認可されていることを確認する。そのうえで、明示的な確認または有効なスコープ付き事前承認を要求する。証拠が欠落または無効な場合はアクションをブロックする。
- 適用される要件で定義されたハード上限と、デプロイメント設定から検証されたより厳しい値を使用する。どちらも値を定義していない場合は、必須の決定事項としてマークし、上限なしの設定を実装が拒否することをテストする。もっともらしい値を作り出してはならない。

## 有効化するタイミング

- 自律エージェント、ツールゲートウェイ、メモリサービス、またはエージェント間プロトコルを構築するとき
- モデル出力をコマンド、パス、URL、認証情報、API ミューテーションにマッピングするコードをレビューするとき
- 長時間稼働するエージェントプロセスでテナント、プロジェクト、セッション、ワークスペースを分離するとき
- 一時ファイル、ログ、ツールレスポンス、外部コンテンツの取り込みを強化するとき

## 強化ワークフロー

### 1. 信頼境界のマッピング

すべての境界を `source -> parser -> validator -> side effect` の形式でリストアップします。直接のユーザー入力、モデル出力、取得したドキュメント、メモリ、環境変数、ツール結果、他のエージェントからのメッセージを含めます。

各副作用について、次を記録します。

- それを認可する識別情報とスコープ
- 副作用の直前に実行される正確なバリデータ
- 入出力の最大サイズ
- 生成される監査証跡
- 操作が中断された場合のリカバリパス

このステップは、すべての書き込み、コマンド、ネットワークミューテーション、認証情報の使用に、名前付きの認可境界が 1 つずつ存在した時点で完了です。

### 2. 識別子、環境値、URL の検証

ファイル名、キー、セレクタ、コマンド引数になる識別子には許可リストを使用します。エージェント ID には Issue で定義されたハード上限の 64 文字が適用されます。デプロイメント設定ではより厳しい正の上限を選択できますが、この境界を引き上げることはできません。

```python
import re

SAFE_AGENT_ID_CHARS = re.compile(r"^[A-Za-z0-9_][A-Za-z0-9_-]*$")
HARD_MAX_AGENT_ID_LENGTH = 64

def require_agent_id(value: object, *, max_length: int) -> str:
    if (
        isinstance(max_length, bool)
        or not isinstance(max_length, int)
        or not 1 <= max_length <= HARD_MAX_AGENT_ID_LENGTH
    ):
        raise RuntimeError("configured agent ID limit must be between 1 and 64")
    if (
        not isinstance(value, str)
        or len(value) > max_length
        or not SAFE_AGENT_ID_CHARS.fullmatch(value)
    ):
        raise ValueError("invalid agent identifier")
    return value
```

識別子が CLI 引数になる場合は、argv API を通して渡し、サポートされている場合はコマンドのオプション終端マーカーの後ろに配置します。文字の検証は引数の分離の代わりにはなりません。

クライアントを構築する前に、欠落している環境値と空白のみの環境値を拒否します。

```python
def require_env(name: str, environ: dict[str, str]) -> str:
    value = environ.get(name)
    if value is None or not value.strip():
        raise RuntimeError(f"{name} is required")
    return value
```

URL をパースし、デプロイメントで必要なスキームのみを許可し、ホストを必須とし、埋め込まれた認証情報を拒否し、URL が攻撃者に制御される場合はプライベートネットワークの宛先をブロックします。すべての外向き接続とリダイレクトホップで、接続を検証済みのパブリックアドレスに固定するか、接続時に接続先ピアのアドレスを検証して、DNS リバインディングが境界を越えられないようにします。認証情報を伴うリクエストは、認証情報を付与する前に、証明書検証付きの HTTPS を使用しなければなりません。オリジンをまたぐ認証情報の自動転送を無効にします。スキームまたはオリジンが変わる場合は、認証情報を削除して新しい宛先を再認可するか、リダイレクトを拒否します。宛先、接続先アドレス、トランスポートの検証をすべてのホップで再実行します。

このステップは、空の値、過大な値、不正な形式の値、トラバーサル形式の値、認証情報を含む値、未認可の宛先が、副作用の前にテストで拒否され、DNS リバインディングとオリジンをまたぐリダイレクトが認証情報を未承認のピアに運べないことが証明された時点で完了です。

### 3. ファイルシステムアクセスのコンテインメント

結合する前に、ユーザー制御の絶対パスとトラバーサルコンポーネントを拒否します。移植性を保つため、Windows で安全でないコンポーネントはすべてのプラットフォームで拒否します。予約済みデバイス名（`CON`、`NUL`、`COM1`、`LPT1`。`nul.txt` のように拡張子が付いたものを含む）、末尾がドットまたはスペースで終わる名前（Win32 が除去する）、および `:`（ドライブ相対、または `report.txt:ads` のような NTFS 代替データストリーム構文）が該当します。ワークスペースと候補パスの両方を解決し、コンテインメントを証明します。

```python
import re
from pathlib import Path

WINDOWS_RESERVED_NAME = re.compile(
    r"(CON|PRN|AUX|NUL|COM[1-9¹²³]|LPT[1-9¹²³])(\..*)?",
    re.IGNORECASE,
)

def workspace_path(workspace: Path, requested: str) -> Path:
    # コンポーネントを確認する前に、両方のプラットフォーム区切り文字を一貫して扱う。
    relative = Path(requested.replace("\\", "/"))
    if relative.is_absolute() or ".." in relative.parts:
        raise ValueError("path must be workspace-relative")
    for part in relative.parts:
        if ":" in part or part.endswith((".", " ")) or WINDOWS_RESERVED_NAME.fullmatch(part):
            raise ValueError("path component is not portable")

    root = workspace.resolve(strict=True)
    candidate = (root / relative).resolve(strict=False)
    if not candidate.is_relative_to(root):
        raise ValueError("path escapes workspace")
    return candidate
```

コンテインメントチェックでは、シンボリックリンクのレース条件は解消されません。機密性の高い書き込みでは、プラットフォームがサポートしている場合は信頼できるディレクトリハンドルからの相対でオープンし、シンボリックリンクのターゲットを拒否し、ファイルを排他的に作成し、オープン後に所有者とパーミッションを検証します。

このステップは、テストが兄弟プレフィックスのパス、ネストされた `..`、絶対パス、シンボリックリンクによる脱出、予約済みデバイス名、末尾のドットまたはスペース、代替データストリーム構文、および有効なネストされたワークスペースパスをカバーした時点で完了です。

### 4. 一時データと認証情報の保護

- 機密ファイルは `0o600` などの所有者のみのパーミッションで作成し、プライベートディレクトリは `0o700` で作成する。
- 認証情報やテナントデータには、共有の一時ディレクトリよりもユーザー専用のランタイムディレクトリを優先する。
- 予測不可能な名前はアトミックに作成する。確認してから作成する（check-then-create）ことはしない。
- 一時データは `finally` で削除し、クリーンアップに失敗した場合は機密値をマスクした（リダクト済みの）エラーレコードを保持する。
- シークレットを、コマンド引数、モデルコンテキスト、ログ、トレース、例外テキスト、ツールレスポンスに含めない。
- シークレットは、プラットフォームのシークレットストアまたはスコープ付き環境変数注入を通して渡し、漏えいした認証情報はローテーションする。
- ゼロ化はベストエフォートとして扱う。可変のバイトバッファは上書きできるが、言語の不変な文字列は確実に消去できない。

このステップは、ファイルモードのチェック、強制エラー時のクリーンアップテスト、ログキャプチャテストによって、シークレット値が承認された境界の外に残らないことが示された時点で完了です。

### 5. ツール出力の制限とサニタイズ

ストリームを無制限に収集するのではなく、バイト制限付きでツール出力を読み取ります。構造化フィールドを保持し、許可されていない制御文字を除去し、元のバイト数を含む明示的な切り詰めマーカーを追加します。後でフォレンジック比較が必要になる場合は、コンテンツのハッシュを保持します。

不正な形式の出力を黙って空の成功値に変換してはいけません。生成元のツール、境界、検証理由を示し、機密コンテンツをエコーしない型付きの失敗を返します。

このステップは、過大な出力、無効なエンコーディング、ターミナル制御シーケンス、不正な形式の構造化データ、および通常のレスポンスのすべてに決定論的なテストがある時点で完了です。

## 検証ゲート

フレームワークを強化済みと呼ぶ前に、実際のエントリポイントを通して次のすべての動作を検証します。

1. 信頼できない指示はデータのままであり、ツールの実行や書き込みを引き起こせない。
2. 操作とリソースに対する認可、および確認またはスコープ付き事前承認がない不可逆なアクションは、副作用を残さない。
3. テナント間およびワークスペース間の識別子は、アクションの境界で拒否される。
4. トラバーサルおよびシンボリックリンクによる脱出の試みは、ファイルシステムを変更しない。
5. 強制的な失敗は、認証情報を含む一時ファイルやログを残さない。
6. 過大または不正な形式のツール出力は、明示的で上限のあるエラーを返す。

使用したコマンド、終了ステータス、拒否された入力、および副作用が存在しないことの観測結果を報告します。モックのみのテストでは、オペレーティングシステムのパーミッション、シンボリックリンクの処理、サブプロセスの分離、ネットワークのエグレス制御を証明できません。

## よくある問題

### 検証がプロンプトの中にしか存在しない

プロンプトの指示は助言にすぎません。同じ不変条件を、副作用の直前の決定論的なコードに移し、それに違反するモデルレスポンスをテストします。

### 正規化されたパスがそれでも脱出する

文字列のプレフィックスチェックは、`/work/app` と `/work/application` のような兄弟パスを取り違えます。パスを解決し、コンポーネント単位のコンテインメントを使用し、シンボリックリンクは別途テストします。

### ログ記録の後にリダクションが行われる

値がロガー、トレーサー、例外、モデルコンテキストに入る前にリダクトします。センチネルシークレットを使ったキャプチャテストを追加し、そのセンチネルが出力されたすべてのチャネルに存在しないことをアサートします。

## 使用しない場合

- 通常のアプリケーションの認証、認可、SQL インジェクション、XSS、CSRF、API セキュリティには `security-review` を使用してください。
- リポジトリ全体の自動脆弱性スキャンには `security-scan` を使用してください。
- ホスト、コンテナ、ファイアウォール、クラウドの強化には、インフラストラクチャ固有のガイダンスを使用してください。
- このスキルをペネトレーションテスト、エクスプロイト開発、不正アクセスに使用しないでください。
