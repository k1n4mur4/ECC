# ヨルバ語ローカライゼーションテスト

**ヨルバ語-英語**のインターフェースを実装またはレビューするときに、このスキルを使用します。自動承認済みの翻訳を提供することが目的ではなく、ヨルバ語の表記、メッセージ処理、ユーザー体験の正確さを対象とします。`i18n-sync`（メッセージの対応関係）および `accessibility`（支援技術のサポート）を補完します。

## 有効化するタイミング

- `yo` または `en` のロケールオプションを持つWebインターフェースやモバイルインターフェースを構築するとき。
- テキスト、入力、検索、保存、エクスポートにおいて、ヨルバ語の声調記号や下付きドットが誤った位置にある、削除されている、または破損している問題を修正するとき。
- 英語へのフォールバック、言語選択、ローカライゼーションのリグレッションテスト、スクリーンリーダー向けの言語メタデータをレビューするとき。
- AIが生成したヨルバ語翻訳を、ユーザーにリリースする前に評価するとき。

## 基本概念

- ヨルバ語には、独立した文字 `ẹ`、`ọ`、`ṣ` と、`á`、`à`、`ẹ́`、`ọ̀` のような声調記号付きの母音が含まれます。声調記号や下付きドットの違いは意味を変えることがあります。
- テキストはUTF-8で保存・送信します。正規の比較や一貫した保存のためにNFCへ正規化しますが、表示テキストから声調記号や下付きドットを取り除いては**いけません**。
- BCP 47の言語タグ `yo` と `en` を優先します。ヨルバ語テキストにはスクリーンリーダー用の言語を設定し（例: Webコンテンツでは `lang="yo"`）、支援技術が実際にその言語をサポートしているかを確認します。
- 機械翻訳で人によるレビューを置き換えてはいけません。意味、自然さ、声調、用語、方言に左右される内容については、流暢なヨルバ語話者によるレビューを必須とします。
- 翻訳が欠けている場合は、ユーザーに分かる形で英語へフォールバックしても構いません。法務、医療、安全、金融に関するコンテンツでは、文字列を黙って捏造してはいけません。
- プレースホルダーとメッセージキーはコード上の契約です。識別子を翻訳したり、補間フィールドを削除したりしないでください。

## 実装ワークフロー

1. 表示されるインターフェースの文字列を洗い出し、安定したロケールキーに抽出します。
2. 欠落キーに対する明示的なフォールバックを備えた `en` と `yo` の辞書を定義し、どの翻訳キーにレビューが必要かを文書化します。
3. Unicodeの合成、句読点、プレースホルダー、スクリーンリーダー用の言語タグ、ユーザーが入力した綴りを保持します。
4. 入力済みのフォーム値やナビゲーション位置を失うことなく、ロケールを切り替えられることを検証します。
5. 正準等価なUnicode、声調記号付きの個別の文字、JSON/API/データベースの往復、翻訳の欠落をテストします。
6. 実際のフォント、モバイルレイアウト、キーボードサポート、スクリーンリーダーを確認し、ローカライゼーションの完了を宣言する前に、流暢なヨルバ語話者の承認を得ます。

## コード例

依存関係のない、実行可能な実装については [`examples/localization.mjs`](../../../../skills/yoruba-localization-testing/examples/localization.mjs) を参照してください。例の文字列は**説明用**であり、ネイティブスピーカーによるレビューの代わりにはなりません。

```javascript
import { translate, sameNormalizedText } from './examples/localization.mjs';

translate('yo', 'welcome'); // 'Ẹ káàbọ̀'
translate('yo', 'logout');  // 'Log out' (English fallback)
sameNormalizedText('ẹ́', 'ẹ\u0301'); // true: canonically equivalent
sameNormalizedText('ẹ', 'e');      // false: different Yoruba letters
```

Webコンポーネントでは、ソーステキストを変更せずに言語を示すために `<span lang="yo">Ẹ káàbọ̀</span>` を使用できます。モバイルでは、プラットフォームで同等の言語メタデータを使用してください。

### リグレッションテストの実行

ECCリポジトリのルートから実行します。

```sh
node skills/yoruba-localization-testing/examples/localization.test.mjs
```

このテストファイルは、ヨルバ語テキスト、英語、フォールバック、Unicode正規化、声調・下付きドットの違いの区別、JSONの往復という、6つの独立したケースを扱います。Node標準の機能のみを使用します（Node 18以降）。

## アンチパターン

- 表示テキストに対する `text.normalize('NFD').replace(/\p{M}/gu, '')`: これは情報を破壊します。
- `ẹ` を `e` に、`ọ` を `o` に、`ṣ` を `s` に置き換えること。
- ヨルバ語話者がヨルバ語のみのUIを望むと決めつけること、またはプログラムの識別子を翻訳すること。
- 十分な能力のある話者によるレビューなしに、自動生成されたヨルバ語の文言を出荷すること。
- フォントのグリフや支援技術を確認せずに、テストが通った時点でローカライゼーションを完了とすること。

## ベストプラクティス

- 翻訳フィクスチャは、バージョン管理下のUTF-8ソースファイルに保管します。
- すべての環境が `yo` を同等にサポートしていると仮定せず、対象のブラウザ／ランタイムで `Intl` のロケール動作を検証します。
- ロケールの切り替えは、元に戻せ、明確にラベル付けされ、キーボードでアクセスできるようにします。
- 問題のある翻訳を報告し、レビュー状況を記録する手段を提供します。
- 英語とヨルバ語が混在した文や、より長いコンテンツを実機でテストします。
