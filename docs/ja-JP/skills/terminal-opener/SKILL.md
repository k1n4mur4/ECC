# Terminal Opener

`scripts/open-terminal.js` を使用して、実行ファイルとすべての引数を個別のプロセスエントリとして保持します。シェルコマンド文字列を補間しないでください。すべての spawn 呼び出しで `shell: false` を維持してください。デフォルトでは、起動せずプランのみを出力する動作にしてください。`--launch` は、ユーザーが実際のウィンドウを明示的に要求し、argv をレビューした後にのみ使用してください。
起動されたプロセスは、呼び出し元プロセスの環境全体（秘密情報を含む変数も含む）を継承します。ランチャーは環境をフィルタリングしません。対象コマンドに公開しても安全な環境のシェルから実行してください。

## コマンドを起動する

ランチャーのオプションを `--` の前に渡し、その後に実行ファイルを1つだけ、続けてその引数配列を渡します。

```bash
node skills/terminal-opener/scripts/open-terminal.js \
  --launch \
  --cwd /absolute/host/path \
  -- ssh -t example.test command-with-arguments
```

まず通常モードで実行します。WezTerm にはまず新しいウィンドウで mux を試させ、mux が利用できない場合は、ランチャーにデタッチ型の `wezterm start` プロセスへフォールバックさせます。フォールバックが使われた場合は、JSON 出力の `muxFailure`（または人間が読める失敗行）を読んで、mux 経路が失敗した理由を診断します。

## ターミナル設定から復旧する

ユーザー設定や mux の状態が要求したコマンドの妨げになる可能性がある場合は、`--recover` または `--standalone` を追加します。次の引数でデタッチされた WezTerm プロセスを起動します。

```text
--skip-config start --always-new-process
```

復旧モードでは、ユーザーのターミナル設定がすべて意図的にスキップされることを想定してください。

## 起動前に確認する

`--launch` を省略（または `--dry-run` を追加）し、`--json` を追加すると、ウィンドウを開かずに、実行ファイル、argv、作業ディレクトリ、ターミナルアダプター、プライマリ起動、およびフォールバックを正確に確認できます。JSON プランは、呼び出し元が組み合わせて利用する際の境界（インターフェース）として扱ってください。

コマンドなしで `--detect --json` を実行すると、ターミナルの利用可否を調べられます。アダプターが存在しない、または未サポートの場合は、返された `action` に従ってください。現在のアダプターには WezTerm を使用します。それ以外のターミナルが要求された場合は、実行すべきコマンドではなく、未サポートのプランとして扱ってください。
