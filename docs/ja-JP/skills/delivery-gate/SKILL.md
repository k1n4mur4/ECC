# Delivery Gate — Claude Code向けの機械的な品質ゲート

Claudeがセッションを終了する前に3つの項目をチェックする**Stopフック**です。使用するのは**決定論的なチェック**のみで、ファイルの更新タイムスタンプ、ディスク使用量、トランスクリプトテキストに対する正規表現パターンを用います。AIによる推論は行いません。

これは推論ゲート（`self-audit`など）とは異なります。delivery-gateは機械的に検証可能な事実をチェックし、self-auditは4つの推論の観点から出力の品質をチェックします。両者を組み合わせることで多層防御を構成します。
- **delivery-gate**: 「学習ライブラリは今日更新されたか？ディスク容量は安全か？」
- **self-audit**: 「ファイルの内容は正確で、完全で、誠実か？」

これはCIパイプラインのゲートと同じパターンです。自己申告のステータスを信頼するのではなく、機械可読な事実を検証する自動化された決定論的チェックです。

## チェック内容

| チェック | 仕組み | 該当時の動作 |
|-------|-----------|--------|
| 合理化パターン | トランスクリプト末尾に対する正規表現 | **警告のみ**（ブロックしない） |
| 古い学習ライブラリ | 設定可能な5つのパスのmtime | 一部が古い場合は警告。複雑なタスクで、3つ以上が古い、またはgrowth-logが古い場合は**ブロック** |
| ディスク容量 < 50GB | `shutil.disk_usage` | リマインド |
| ディスク容量 < 30GB | `shutil.disk_usage` | 警告 |
| ディスク容量 < 15GB | `shutil.disk_usage` | **ブロック**（exit 2）。すべてのStopで実施 |

合理化の検出では「skip tests for now」や「pre-existing bug」のようなパターンを警告します。これらは思考が途中で打ち切られた可能性を示す表層的なシグナルです。正規表現のヒューリスティックは誤検出する可能性があるため、これ単体ではブロックしません。ブロック条件は、ディスク容量が危険水準（15GB未満。どのセッションでも）であるか、複雑なタスク（Edit/Write呼び出しが3回以上）で、`>=3 learning libs stale`（3つ以上の学習ライブラリが古い）または`growth-log`が特に古い場合です。プロジェクトのメモリディレクトリが存在しない場合、学習ライブラリのチェックはスキップされます。フックは学習の記録を検証できないという警告を出すだけで、複雑なタスクもブロックされません（ディスクのチェックは引き続き適用されます）。

このフックは1回のStopに対して最大1回だけブロックします。Claude Codeが`stop_hook_active: true`でフックを再実行した場合（このフックが原因でClaudeがすでに1回継続した場合）、exit 0で終了します。これにより、ディスク容量不足のようにエージェントが解決できない状況で、セッションが無限ループに陥ることを防ぎます。

## 理由

Claude Codeの組み込みチェックは、コード品質（ビルド → 型 → lint → テスト）を対象にしています。しかし、それとは異なる失敗モードがあります。エージェントは動作するコードを生成しても、**セッションの衛生管理**がおろそかになることがあります。学習が記録されない、合理化によって近道が取られる、ディスク容量が気づかないうちに少なくなっていく、といった状況です。

「出荷して忘れる」セッションが何度も続くと、人間が成長しません。このフックはその習慣を強制します。複雑なタスクを行ったなら、学習ライブラリを更新しなければなりません。

## インストール

ECCリポジトリのルートから実行します。

```bash
mkdir -p ~/.claude/scripts
cp skills/delivery-gate/hooks/quality-gate.py ~/.claude/scripts/
```

`~/.claude/settings.json`に追加します。
```json
{
  "hooks": {
    "Stop": [{
      "hooks": [{
        "type": "command",
        "command": "python3 ~/.claude/scripts/quality-gate.py",
        "timeout": 5
      }]
    }]
  }
}
```

## 学習ライブラリ

プロジェクトのメモリディレクトリ（`~/.claude/projects/<encoded-project-path>/memory/`。プロジェクトパスの英数字以外の文字はすべて`-`になります）に、以下のファイルを作成します。フックは、これらのうちどれが今日更新されたかをチェックします。

```
memory/
├── growth-log/          # 日々の学習エントリ（ディレクトリ）
├── decisions/log.md     # 意思決定ログ
├── output-index.md      # セッション成果物のインデックス
├── ratings-tracker.md   # スキル評価の推移
└── tooling_capabilities.md  # 既知のツール一覧
```

`LIBS`辞書は、ご自身のファイル構成に合わせてカスタマイズしてください。

## 設定

`quality-gate.py`を編集します。

| 変数 | デフォルト | 目的 |
|----------|---------|---------|
| `RATIONALIZE` | 4パターン | 合理化検出用の正規表現パターン |
| `LIBS` | 5ライブラリ | 今日の更新をチェックするファイル/ディレクトリ |
| `COMPLEX_THRESHOLD` | 3 | 複雑なタスクと分類するEdit/Write呼び出し回数 |
| `DISK_REMIND_GB` | 50 | これを下回るとリマインド |
| `DISK_WARN_GB` | 30 | これを下回ると警告 |
| `DISK_CRIT_GB` | 15 | これを下回るとブロック |

## 例

**単純なセッション — 許可:**
```
edit_count=1 (< 3, not complex) → exit 0
```

**複雑なタスク、学習が記録済み — 許可:**
```
edit_count=5 (complex) → checks LIBS → growth-log + 2 others updated today (2 stale) → exit 0
```

**複雑なタスク、学習なし — ブロック:**
```
edit_count=4 (complex) → checks LIBS → all 5 stale → exit 2
stderr: "Blocked: complex task but >=3 learning libs stale."
```

**ディスク容量不足 — ブロック:**
```
disk_free=12GB < 15GB critical → exit 2
stderr: "Blocked: disk space at 12GB (<15GB). Free space before continuing."
```

## 制限事項

このフックが強制するのは学習ライブラリを更新するという**習慣**であり、記録された内容の**品質**ではありません。複雑なタスクでは、`growth-log`が今日更新されており、かつ古いライブラリが2つ以下の場合にのみ通過します。`output-index.md`だけを更新してもブロックされます。プロジェクトのメモリディレクトリがない場合はチェック対象がないため、警告のみを行います。これは意図的な設計です。機械的なゲートは機械的に検証可能な事実をチェックします。内容の品質検証には`self-audit`と組み合わせてください。
