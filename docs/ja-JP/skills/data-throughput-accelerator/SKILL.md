# データスループット・アクセラレーター

大量のデータの移動、変換、保存がボトルネックになっている場合にこのスキルを使用します。目的は単なる速度ではありません。目的は、正しいデータをより速く、適切な場所に、証拠とともに届けることです。

## 最初の区別

最適化する前に、次を切り分けます。

- ソースからの抽出速度
- ネットワーク転送速度
- ウェアハウスへのロード速度
- 変換速度
- サービング用テーブルの鮮度
- ジョブ実行中のライブテールの増加

新しいデータが最終的なキャッチアップ期間よりも速く到着する場合、パイプラインは「高速」であっても遅れているように見えることがあります。

## 高速経路のヒューリスティック

- 計算処理を、データがすでに存在する場所へ移します。
- ランディング済みの大きなファイルには、ウェアハウスネイティブのスキャン、結合、追記を優先します。
- マニフェストやチェックポイントを使い、完了済みのファイルやパーティションをスキップします。
- 読み取りと追記のパターンに合ったパーティショニングとクラスタリングを使います。
- 小さなファイル、リクエスト、書き込みをバッチ化します。
- 一意キー、マニフェスト、または置き換え可能なステージングによって、書き込みを冪等にします。
- raw、派生、サービングの各テーブルを個別に集計可能な状態に保ちます。

## ワークフロー

1. 現在のソース、ターゲット、マニフェストの契約を読みます。
2. バックログを計測します(外部ファイル、マニフェスト行、raw 行、派生行、最小/最大タイムスタンプ、未処理件数)。
3. 安全なキャッチアップまたはサンプルのベンチマークを実行します。
4. バリアントを比較します(バッチサイズ、ワーカー数、ウェアハウス SQL、ファイルのグルーピング、ステージングの形状、マニフェストの更新方法)。
5. 件数とタイムスタンプの整合性が保たれる最速の経路のみを採用します。
6. その経路を CLI、スケジュールジョブ、ワークフロー、またはランブックとして定型化(コード化)します。
7. 定型化した経路の実行後に、最終的な集計を再度実行します。

## 集計の出力

厳密な集計ブロックを使います。

```text
Data throughput result:
- Source files discovered: 294
- Files processed this run: 294
- Raw rows added: 9,683,598
- Derived rows added: 8,917,585
- Remaining tail: 24 files at readback time
- Runtime: 38.7s
- Correctness gate: manifest counts and table max timestamps match
```

## ガードレール

- 指標をよく見せるために raw データを削除しないでください。
- 失敗したファイルを黙ってスキップしないでください。
- 過去分のバックフィルの状態と、ライブテールの鮮度を混同しないでください。
- ターゲットテーブルとマニフェストが一致するまで、パイプラインを完了と呼ばないでください。
- 金融、ヘルスケア、規制対象、または顧客に影響するデータでは、リプレイの証跡と承認ゲートを保持してください。
