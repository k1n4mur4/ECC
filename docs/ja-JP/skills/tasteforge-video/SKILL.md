# TasteForge Video

スタンドアロンのクリエイティブパイプライン全体には、`taste-distillation` の後に
`taste-application` を使用します。これらの ECC スキルは Python スクリプトを直接同梱しており、
リファレンスの計測、既存テイクの生成またはパススルー、グレーディング、カット、
コンポジット、検証、Blender と Resolve へのハンドオフまでを行います。このフローに別途の動画リポジトリは不要です。このスキルは、ECC にパッケージ化されたオフラインエンジンと、その厳格なエビデンス契約を説明します。

TasteForge は「このリファレンスのような雰囲気にして」という依頼を、再現可能で検査可能なワークフローに変換します。
テイストをインタビューし、構造化されたスタイルパックへ蒸留し、パックを検証し、
計測済みのカデンスとルックをローカルメディアに適用し、編集可能なタイムラインをエクスポートします。
正規の実装は、ECC 内の `skills/taste-application/scripts/tasteforge/` に同梱されている
`tasteforge` パッケージです。`Ito-Markets/ito-video` は、パッケージ化された ECC エンジンを利用するサンプルプロジェクトです。

## 使用するタイミング

- 映像を作る前に**動画のテイストについてインタビュー**するよう求められたとき
  （「ルックについて質問して」「美的方向性についてインタビューして」）。
- **美的感覚を構造化された制約へ蒸留**したいとき。雰囲気ではなく再利用可能なスタイルパックにします
  （「これらのリファレンスをパックにして」）。
- **スタイルパックを検証**したいとき（メタデータは完全か、スキーマに適合しているか、カデンスは計測済みか、スペックは蒸留済みか）。
- **スタイルパックをローカル映像に適用**したいとき。パックの計測済みカデンスから、ローカルクリップに対するカットを決定論的に計画します。
- **EDL/FCPXML をエクスポート**したいとき。DaVinci Resolve / Premiere / Final Cut へのフレーム単位で正確な、編集可能なハンドオフです。
- **生成メディアの来歴監査**を求められたとき。このパック、スペック、カットがどこから来たのか、ローカルで計測されたものとプロバイダーが生成したものは何か、何がドライランだったのかを確認します。
- ローカルのリファレンスファイルから、**ファイル駆動のマルチモーダルな画像・動画・3Dアセット出力の探索または計画**を求められたとき。個別のマニフェスト、被写体アンカー付き CV エフェクト、Resolve エフェクトレシピを含みます。
- TasteForge、スタイルパック、flashethereal、テイスト蒸留、カデンス/リズム計画、マルチモーダル探索、distill/apply ワークフロー、または動画のテイストインタビューに言及されたとき。

## ローカルの決定論的操作とプロバイダー生成

この境界が、この互換性スキルの中核です。このスキルの操作は
**ローカルで、決定論的で、オフライン**です。

| 操作 | 決定論的か | ECC が実行可能か |
|---|---|---|
| テイストインタビュー → プロファイル | はい（オフライン） | はい |
| パックの検査 / スキーマに対する検証 | はい | はい |
| プロファイル（＋計測済みグラウンディング）の蒸留 → スペック | はい（ドライランのセマンティクス） | はい |
| パックのカデンスをローカルメディアに適用 → レポート＋タイムライン | はい | はい |
| EDL（CMX3600）/ FCPXML 1.9 のエクスポート | はい | はい |
| 来歴 / 系譜レポート | はい | はい |
| 静止画のビジョンモデル蒸留 | **プロバイダー生成** | **いいえ** |
| リファレンスから動画、画像から 3D、ホスト型コンポーズ | **プロバイダー生成** | **いいえ** |

**プロバイダー生成は ECC では fail closed でなければなりません。** Fal（またはその他のプロバイダー）の
ライブ呼び出し（ショットの生成、プロップメッシュの生成、ホスト型 VLM 蒸留）は、
独自のレビューを伴う別レーンで、明示的かつ個別に承認された実行が必要です。この互換性レーンでは、ECC は Fal を呼び出さず、
API キーやその他の認証情報（`FAL_KEY` を含む）を読み取らず、メディアをアップロードせず、
プロバイダーアカウントの状態も変更しません。リクエストがプロバイダー生成を必要とする場合は、
まさにその境界を明示し、ローカル側の作業（インタビュー、パック検証、計画、エクスポート）を実行して、そこで停止します。

**Fal ワークフローが保存されたと主張してはいけません。** Fal エンドポイント、モデル ID、ドライラン URL へのローカルな参照
（パックのメタデータ内に現れます）は**参照専用**です。プロバイダー側のワークフローが保存された、永続化された、
または実行を承認されたことを意味することはありません。オフラインで生成されたものはすべて
dry-run/dry_run のセマンティクスを持ちます。「ドライランスペック」や「決定論的プラン」と言い、
「モデルが生成した」とは決して言わないでください。

## 正規の実装

- リポジトリ: `affaan-m/ECC`。Python ディストリビューションは `ecc-tasteforge`、パッケージ
  ディレクトリは `skills/taste-application/scripts/tasteforge/` です。展開した ECC パッケージから
  `python3 -m pip install ./skills/taste-application/scripts` でインストールします。
  サンプルプロジェクト `Ito-Markets/ito-video` は特定の ECC コミットに固定されています。
- CLI: `python3 -m tasteforge <command>`。コマンドは `provenance`、`inspect`、`validate`、
  `interview`、`distill`、`apply`、`export`、`multimodal` です。`--live` フラグは
  終了コード 2 で終了し、拒否されます。
- スキーマが契約です。テイストプロファイル、パックマニフェスト、グレード、カデンス、
  スペック、タイムラインイベント、アプリケーションレポート（`provider` は `"none"` に、
  `dry_run` は `true` に enum で固定されています）が対象です。
- 復元されたソースの系譜と意図的な除外項目は、リポジトリの
  `skills/taste-application/SOURCE.md` にあります。機械可読な版は `python3 -m tasteforge provenance` を実行して取得します。

ローカルの決定論的コマンドにはインストール済みの ECC エンジンを使用し、その JSON を解釈します。
パッケージ化されたエンジンがなければインストールしてください。そのロジックをインラインで再構築してはいけません。`taste.resolve` は
`tasteforge.resolve` の互換インポートであるため、クリエイティブスクリプトとサンプルプロジェクトは、検証済みの単一の Resolve アダプターを共有します。

`python3 -m tasteforge` CLI は、インストール済みの `ecc-tasteforge` ディストリビューションを使用します。スタンドアロンの `taste-distillation` と `taste-application`
スクリプトは、ECC のオプトイン式メディア生成モジュールに、独自の Python 要件とともに同梱されています。
どちらの経路でも、ユーザーのリポジトリやメディアを公開する必要はありません。

保存済みのチェックアウトを再開する前に、そのコミットを記録し、ローカルブランチと
ワークツリーに後続の実装修正がないか確認します。正規パッケージのテストと
`python3 -m tasteforge apply --help` を実行してください。ECC のテキストおよびフィクスチャテストでは、
選択した Python チェックアウトがこの契約を実装していることは証明できません。

## クリエイティブスキルの連携

| ステージ | 担当 | レビュー可能な成果物 |
|---|---|---|
| クリエイティブディレクション | `taste` | 名前付きジャンル、リファレンスの観察、選択したルックと回避リスト |
| 蒸留と計画 | `tasteforge-video` | 計測済みエビデンス、ジャンルごとの個別スペック、ドライランマニフェストとカデンス計画 |
| 編集とエフェクト | `video-editing`（Remotion、Manim、Fusion などの選択したレンダラーと併用） | 適用済み映像、実際のトラック、編集可能なエフェクトとタイムライン |
| オプションの生成アセットまたは音声 | `fal-ai-media` または選択した音声ワークフロー（それぞれ独自の承認の下で） | プロバイダーのレシートと検査済みの出力 |
| 納品 | 編集ワークフロー。要望があれば続けて `content-engine` | レビュー済みの正確なエクスポートと配信用コピー |

プロジェクトが必要とするステージだけを使用してください。`taste` スキルの
歴史的な angelcore/cloud-trance パレットとビート文法は、任意のクリエイティブ例であり、
現在のブリーフを上書きしたり、番号付けされた別々のジャンルを統合したりしてはいけません。
各ジャンルの方向性には、3D Cyber Glitch と Fluid Sketch を含め、そのジャンル固有のリファレンスを使用します。
TasteForge はこれらのスキルを置き換えるものではなく、すべてのレンダラーを必須とするものでもありません。
3D のマテリアル、ジオメトリ、ワイヤーフレームの挙動、
モーション、構図は、ジャンルシグネチャの中で明示的に保ってください。3D リクエストマニフェスト
はアセットの計画であり、メッシュではありません。被写体アンカー記述子はトラッキング要件を示すものであり、
被写体が検出またはトラッキングされた証拠ではありません。
CV エフェクトが確実に適用されたと主張する前に、実際のトラック、トラック喪失時の挙動、
レンダリングされた被写体フレームを検査してください。

## ワークフロー

1. **インタビュー**（`interview`）: ルックの各軸（パレット、
   グレイン、ライティング、焦点距離、カメラモーション、被写体のフレーミング、グレード、
   ムードを表す形容詞、回避リスト）と、別途コンテンツブリーフの回答を収集します。ルックと
   コンテンツは分けて扱ってください。両者を混ぜるのが典型的な失敗です。
2. **蒸留**（`distill`）: オフラインでプロファイルをスペックスキーマにマッピングし、
   パックが与えられた場合はそのパックの計測済みグラウンディング（黒点/白点、コントラスト、
   ゾーンごとのクロマ、パレット、カットのリズム）を埋め込みます。結果は
   ドライランスペックで、決定論的であり、プロバイダーは `"none"` です。
3. **検証**（`validate` / `inspect`）: パックをそのスキーマに対して検査し、
   エラーと警告を報告します（メタデータのみのパックで静止画が欠けている場合は
   エラーではなく警告です）。
4. **適用**（`apply`）: パックの計測済みカデンスから、ユーザーのローカルクリップに対する
   ショット尺を計画し（シード付きで決定論的）、アプリケーションレポートと
   フレーム単位で正確なタイムラインイベントを生成します。
5. **エクスポート**（`export`）: 実際の NLE にインポートするため、有理数で NTSC セーフな時間を用いた
   CMX3600 EDL と FCPXML 1.9 を書き出します。
6. **監査**（`provenance`）: 系譜を報告します。復元ソースのダイジェスト、
   生成履歴、フィクスチャの来歴、ポインタのみのレコードとしてのプロバイダー参照が含まれます。

### 同じソースを繰り返さずに実映像へ適用する

ブリーフがクリップの繰り返しなしを求める場合は、`apply --no-repeat --fps` をサポートする
正規チェックアウトを使用し、出力フレームレートを明示的に設定します。これらの
フラグがない場合は、レガシーのラウンドロビン選択を黙って使用するのではなく、実装のギャップとして報告してください。厳格モードでは、正規化された各ソースパスを
マニフェスト順に最大 1 回だけ使用し、不足しているソースや短すぎるソースを拒否します。
カデンス計画を満たすのに十分な、レビュー済みのセレクトを用意してください。これはソース単位の
一意性であり、同じ録画から異なるイン/アウト範囲を使うことのサポートではありません。

アプリケーションレポートはカット計画です。視覚的なショットのランク付け、映像のグレーディング、LUT の適用、
オーバーレイのレンダリング、Resolve プロジェクトのインポートは行いません。
パックの計測済みリファレンスカデンスと、出力フレームレートは分けて扱ってください。

エクスポート CLI は `{"clips": [...]}` を期待します。エクスポートする前に、アプリケーションの
`timeline_events` を `clips` の下にラップし、適用時に使用したものと同じ `--fps` を渡してください。エクスポートの既定のフレームレートによって計画を再変換（リコンフォーム）してはいけません。
タイムラインを編集ワークフローに渡す前に、出力されたイベント数、総フレーム数、一意のソース数、
メディアのリンクを確認してください。
そのワークフローが NLE で重なり合うエフェクトを適用する場合は、互換性のある
トラックを割り当て、要求されたすべての開始、終了、尺を読み戻してください。返されたアイテムや、
追加呼び出しの成功だけでは、スケジュールされたすべてのエフェクトが配置されたことの証明にはなりません。
レンダリングの前に、欠落、ずれ、切り詰められた配置を拒否してください。

## ファイル駆動のマルチモーダル契約

ローカルのリファレンスが、ジャンルの分離を保ちながら、画像、動画、3Dアセット出力の
ドライラン生成計画を駆動する必要がある場合に、この経路を使用します。

```bash
python3 -m tasteforge multimodal --config workflow.json --out-dir out/multimodal
```

設定ファイルには、番号付きのジャンルとローカルのエビデンスファイルを指定します。以下の候補ジャンルは
1 つの汎用的な美的感覚に混ぜずに、別々に保ってください。

1. Flash Ethereal
2. 3D Cyber Glitch
3. Fluid Sketch

このコマンドは ffprobe/ffmpeg でローカルのリファレンスを計測し、ジャンルごとに 1 つのスタイル
スペック、画像・動画・3Dアセットそれぞれの個別マニフェスト、来歴、
Resolve エフェクトレシピを出力します。エフェクトのスケジュールはシード付きの非周期でなければなりません。CV
エフェクトには実在する被写体アンカーが必要で、その喪失時ポリシーは厳密に
`disable_effect_until_track_recovers` でなければなりません。`continue_without_anchor` を含む
その他のポリシーはすべて fail closed となります。すべてのエフェクトは、顔と判読可能な文字を
保護し、装飾的なコーナーメッシュがフルフレームの 3D 作業に取って代わることを防ぐ配置制約を持ちます。

返されるレシートがバンドルの境界です。レシートは、出力されたすべてのエビデンス成果物を、
相対パス、バイトサイズ、SHA-256、ジャンル、モダリティ、
`provider_execution:false`、および正確なリファレンス/時間の来歴によって束縛します。レシートには
`provider_calls:0` が厳密な整数であること（JSON のブール値 `false` は
無効）、`provider_execution:false`、`dry_run:true` が必要です。すべてのジャンルスペックにも
明示的な `dry_run:true` が必要です。Resolve エフェクトレシピにも、同じ厳密な整数
`provider_calls:0`、`provider_execution:false`、`dry_run:true` が必要です。
すべてのモダリティマニフェストとすべてのネストされたリクエストは、fail closed のための 4 つの厳密なフィールド
（整数の `provider_calls:0`、`provider_execution:false`、
`dry_run:true`、`submit:false`）をすべて含まなければならず、各リクエストにはさらに
`provider_call_mode:"disabled"` が必要です。フィールドの欠落はデフォルト値ではなく拒否の対象であり、
`dry_run:false` は出力が書き込まれる前に拒否されなければなりません。

タイムライン、エビデンス、プローブ、ソース尺のデータでは、ブール値をどこでも無効な数値として扱ってください。
そのような数値はすべて有限の実数でなければなりません。`true`、`false`、NaN、無限大、負のイベント開始時刻、
正でない尺、範囲外のエビデンス時刻、宣言された有限の正のタイムラインを超えて終わるイベントは拒否します。
ファイル全体のエビデンスは、明示的なファイル全体の時間基準を使用し、
タイムスタンプを捏造しません。

尺の正となる情報源はレシートのリファレンスです。検証済みの各リファレンスの
尺を、引用された SHA-256 をキーにして管理します。同じダイジェストが複数回現れる場合は
尺が一致しなければならず、一致しなければバンドルは無効です。すべてのエフェクトエビデンスの `source_duration`
とすべての被写体アンカーの `source_duration` は、単に引用された時刻を含むだけでなく、
そのダイジェストの検証済みレシート尺と等しくなければなりません。プローブの尺とすべての
プローブ計測値は、バイト数と SHA-256 に使用したものと同じ安定したバイト列を
記述していなければなりません。プローブ中にソースが変更された場合、または
まだ利用可能な状態で異なるハッシュになる場合は、レシートを出力または受理せず、
fail closed としてください。

作成後は必ずバンドル検証を実行してください。画像、動画、3Dアセットのマニフェストが 1 つでも欠けている場合は
fail closed でなければなりません。汎用化または重複したジャンル、周期的なスケジュール、
アンカーのない CV エフェクト、配置制約の欠落、プロバイダー実行フラグ、束縛されていない出力ファイル、
バイトサイズのずれ、SHA-256 の改ざんも、fail closed でなければなりません。
出力ルート、中間ファイル、成果物がシンボリックリンクの場合は拒否し、
特殊ファイル（FIFO やデバイスを含む）も拒否してください。出力は実在するディレクトリツリーの下の
通常ファイルでなければなりません。ローカルの `ffmpeg` または `ffprobe` が利用できない場合、
CLI は、Python のトレースバックを出さずに、ゼロ以外の終了コードを伴う簡潔なローカルメディア処理エラーを
返さなければなりません。エビデンスを削除したり検証を弱めたりして、失敗したレシートを修復しないでください。

## セッション例

```bash
# ECC エンジンのインストール後。以下のパスはプロジェクトの入力です
python3 -m tasteforge validate stylepacks/flashethereal
python3 -m tasteforge interview --answers answers.json --genre flashethereal --out profile.json
python3 -m tasteforge distill --profile profile.json --pack stylepacks/flashethereal --out spec.json
python3 -m tasteforge apply --pack stylepacks/flashethereal --media media.json --duration 20 --out report.json
python3 -m tasteforge export --events events.json --out-dir out --title flashethereal-cut
python3 -m tasteforge provenance
```

ショットを生成する必要がある場合は、ユーザーの明示的なプロバイダー承認の下で、レビュー済みのブリーフと
スタイルの方向性を `taste-application` に渡します。
オフライン CLI は fail closed のままであり、その計画や編集可能なタイムラインは、
プロバイダーのジョブが実行されたことの証明にはなりません。
