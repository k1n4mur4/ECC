# Blender モーション状態の検査

## 使用タイミング

- Blender のキャラクターがアニメーション中にねじれている、ミラーされている、つぶれている、オフセットしている、または足が滑っているように見える。
- インポートしたアバター、アーマチュア、またはリターゲットしたモーションが期待するポーズと一致しているかをユーザーが尋ねている。
- レンダリング結果の証拠を、ボーン、バウンディングボックス、接地、向きベクトルといった構造化された事実と比較する必要がある。
- あるモデルがキャラクター、プロップ、プロキシメッシュ、コントロールリグ、または壊れたインポートのいずれであるかを判断することにワークフローが依存している。

## 基本原則

アニメーションする 3D アセットを、スクリーンショットだけで判断してはいけません。スクリーンショットはレビュー用の証拠ではありますが、軸の規約、ボーン名、オブジェクトのスケール、ローカルトランスフォーム、親子付けされたメッシュ、マテリアルスロット、フレームごとの接地状態は隠してしまいます。

まず構造化された Blender の状態を抽出し、その後にビューポートのスクリーンショットやレンダリングを使って、その事実が示唆する内容を確認します。

## 仕組み

1. モーションを判断する前に、クリーンなシーンとアセットのベースラインを確立します。
2. エクスポーター、または Blender 自身のインタープリタ内で実行する Blender Python を使って、Blender から構造化された事実を抽出します。
3. 接地、向き、スケール、リターゲティングの誤りが最も現れやすいフレームをサンプリングします。
4. 計測した事実を、ユーザーが期待するポーズ、向き、地面の平面、レンダリングの目標と比較します。
5. 確認済みの事実、考えられる原因、必要な修正を切り分けた簡潔なレポートを返します。

## 検査ワークフロー

1. シーンの棚卸しを行います。
   - メッシュ、アーマチュア、エンプティ、カメラ、ライト、モディファイア、親子関係、非表示オブジェクトを一覧にします。
   - アバターを判断する前に、キャラクターのメッシュとヘルパー／プロキシのジオメトリを分けます。
   - オブジェクト空間とワールド空間のバウンディングボックスを記録します。

2. スケルトンを特定します。
   - アーマチュア名、ポーズボーン、ボーンの head/tail、ロール、親チェーン、コンストレイント、レストポーズの軸を取得します。
   - hips、spine、neck、head、shoulders、elbows、hands、thighs、knees、ankles、feet といった意味的なボーンを対応付けます。
   - 左右のペアの欠落や、通常とは異なる命名規則を指摘します。

3. 前方・上方・側方の軸を判定します。
   - 骨盤、背骨、肩、腰、頭、足をあわせて使います。単一のメッシュ法線に頼ってはいけません。
   - アーマチュアのローカル軸を、ワールド軸や、glTF の Y-up と Blender の Z-up のようなインポート元ファイルの規約と比較します。
   - 顔・頭・足の向きがルートモーションと矛盾する場合は、ミラーまたは後ろ向きのインポートの可能性があるとマークします。

4. アニメーションフレームをサンプリングします。
   - 最初、中間、接地、空中、極端なポーズのフレームを調べます。
   - ルートの位置、ルートの向き、骨盤の高さ、胴体の傾き、四肢の方向、足のクリアランス、メッシュのバウンディングボックスを記録します。
   - 長いモーションや速いモーションでは、宙返り、着地、旋回、衝突、床との接地の前後をより密にサンプリングします。

5. リターゲティングのせいにする前に、モデルの整合性を確認します。
   - アニメーションを適用する前に、クリーンなベースラインの形状を確認します。
   - ユーザーが明示的に修復を求めない限り、元のメッシュ、マテリアル、アーマチュア、スキニングを保持します。
   - 原因不明の球状の塊、巨大なプロキシメッシュ、つぶれた体は、そうでないと証明されるまでインポートまたは選択の問題として扱います。

6. 接地とモーションの問題を診断します。
   - 地面へのめり込み: フレームごとに、最も低い足または靴の頂点と床の高さを比較します。
   - 足の滑り: 接地しているフレーム間で、足のワールド位置を比較します。
   - 脚の交差: 左右の thigh、knee、ankle、foot の並び順を比較します。
   - ねじれによる破綻: ボーンのスイング方向を、四肢の軸まわりのロール／ねじれとは別に比較します。
   - スケールのずれ: アニメーション後のメッシュのバウンディングボックスを、クリーンなベースラインのバウンディングボックスと比較します。

7. 意見よりも先に事実を報告します。
   - フレーム番号、オブジェクト名、ボーン名、ワールド座標、しきい値を含めます。
   - 確認済みの不具合と、見た目上の疑いを切り分けます。
   - スクリーンショットは、構造化された状態によって何に注目すべきかが説明できてから添付します。

## 例

### 足が滑るウォークサイクル

シナリオ: リターゲットしたキャラクターがウォークサイクル中にスケートのように見えるが、正面のカメラアングルでは足の接地を判断しにくい。

ワークフローの適用:
- シーンの棚卸し: キャラクターメッシュ `HeroBody`、アーマチュア `HeroRig`、地面の平面 `Floor`、非表示のプロキシメッシュなし。
- スケルトンの特定: 意味的な足は `foot.L` と `foot.R`、腰は `pelvis`、ルートボーンは `root`。
- アニメーションフレームのサンプリング: 足が接地する瞬間の前後にあたるフレーム 1、18、24、30、42、48 を調べる。
- 接地とモーションの問題の診断: 接地しているフレーム中の足のワールド位置を比較する。

抽出した事実:

| Frame | Fact | Evidence |
| --- | --- | --- |
| 18 | 左足が接地している | `foot.L min_z = 0.004`、つま先とかかとの両方が床の近く |
| 24 | 左足が接地中に滑っている | 6 フレームにわたって `foot.L x = 0.21 -> 0.28` |
| 30 | 骨盤が前進し続けている | `pelvis y = 1.14 -> 1.31` |

判定: レンダリング準備としては不合格です。モーションにはフットロックのクリーンアップまたはリターゲティングのコンストレイントの見直しが必要です。ボディメッシュのプロポーションを変更する必要はありません。

### 後ろ向きにインポートされたキャラクター

シナリオ: キャラクターは静止フレームでは正しく見えるが、アニメーションが期待する進行方向と逆に動く。

ワークフローの適用:
- 前方・上方・側方の軸の判定: 頭、胸、足、ルートモーションを比較する。
- アニメーションフレームのサンプリング: フレーム 1 と移動経路の中間点を調べる。
- 意見よりも先に事実を報告: ルートの向きとモデルの向いている方向を別々に記載する。

抽出した事実:

| Frame | Fact | Evidence |
| --- | --- | --- |
| 1 | キャラクターの顔がワールドの `-Y` を向いている | `neck` から `head` へのベクトル（頭／胸の向き）が `-Y` になる |
| 72 | ルートモーションがワールドの `+Y` 方向に進む | `root y = 0.0 -> 2.8` |
| 72 | 足が見た目上、進行方向と逆の前向きのままである | 変位は `+Y` なのに、つま先のボーンは `-Y` を向いている |

判定: 後ろ向きのインポート、またはリターゲティングにおける前方軸の不一致の可能性が高いです。アニメーションカーブを編集する前に、インポート／リターゲットの軸マッピングを修正します。

## 実用的なしきい値

- シーンの単位スケールが別途指定されていない限り、Blender のデフォルトであるメートル単位を前提とします。
- 床が柔らかい場合や意図的にスタイライズされている場合を除き、1〜2 cm を超える地面へのめり込みは目に見えるものとして扱います。
- 5% を超える急なスケール変化は、リグ、コンストレイント、またはトランスフォーム継承の問題の可能性が高いものとして扱います。
- 空中で上下が逆さまになるモーション中に左右の足首の並び順が入れ替わる場合は、後で回復するとしても、脚の交差のリスクとして扱います。
- 元のモーションにスナップターンが含まれない限り、ルートの向きが 1 フレームあたり 30 度を超えて跳ぶ場合は不審なものとして扱います。

## アンチパターン

- タスクが明示的にメッシュの修復でない限り、ポーズを合わせるためにボディのプロポーションを変更しないこと。
- クリーンなベースラインを記録する前に、ベイクして消してしまわないこと。
- 1 つのレンダリングカメラアングルを、ポーズが正しいことの証拠として使わないこと。
- ヘルパーオブジェクトがキャラクターの一部でない理由を記録するまでは、削除しないこと。
- 頭、足、胴体、ルートモーションをあわせて確認せずに、アバターが +Y、-Y、+X、-X のどちらを向いているかを決めつけないこと。

## ツールに関する注意

Blender の状態エクスポーターが利用できる場合は、メッシュ、アーマチュア、ポーズボーン、マテリアル、接地、バウンディングボックス、サンプリングしたアニメーションフレームを含む JSON を優先します。エクスポーターがない場合は、小さな Blender Python スクリプトを Blender 自身で実行します（例: `blender --background scene.blend --python collect_motion_state.py`）。`bpy` は通常のシステムの Python インタープリタでは利用できないためです。
